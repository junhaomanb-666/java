## Java-001 `new String()` 与字符串拼接

**题目：**

下面程序的运行结果是？

```java
String str1 = "hello";
String str2 = "he" + new String("llo");
System.err.println(str1 == str2);
```

**选项：**

- A. `true`
- B. `false`
- C. `exception`
- D. 无输出

**正确答案：** B

**你的答案：** C

**解析：**

`str1 = "hello"` 中的 `"hello"` 会进入字符串常量池。

`str2 = "he" + new String("llo")` 中，右侧包含 `new String("llo")`，不是纯编译期常量拼接，因此拼接结果会在运行期产生新的 `String` 对象。

`==` 比较的是两个引用是否指向同一个对象。`str1` 指向字符串常量池中的 `"hello"`，`str2` 指向运行期新创建的字符串对象，所以结果是：

```text
false
```

**考点：**

- 字符串常量池
- 编译期常量拼接
- 运行期字符串拼接
- `==` 与 `equals()`

**易错点：**

- `==` 比较引用地址，不比较字符串内容
- 只要拼接表达式里有运行期对象，通常不会直接指向常量池里的同一个对象

## Java-002 字符串常量拼接与变量拼接

**题目：**

原文件中该题为牛客远程图片，当前 Markdown 只保留了解析文字，未保留本地题图。根据文件中的解析，还原题意如下：

**原文件解析图片：**

![字符串常量池解析](https://uploadfiles.nowcoder.com/images/20190618/117596164_1560821319150_ACED241801E307EE7A39612F85A94EBF)

判断类似代码中 `==` 的结果：

```java
String str1 = "hello";
String str2 = "he" + "llo";
System.out.println(str1 == str2);

String a = "llo";
String str3 = "he" + a;
System.out.println(str1 == str3);
```

**选项：**

原远程图片选项未完整保留；按题意应判断两次输出结果。

**正确答案：**

```text
true
false
```

**你的答案：** 未记录

**解析：**

`"he" + "llo"` 两边都是字符串字面量，编译器会在编译期优化为 `"hello"`，所以 `str2` 和 `str1` 都指向字符串常量池中的同一个 `"hello"` 对象：

```java
str1 == str2 // true
```

`"he" + a` 中的 `a` 是变量，即使它的值也是 `"llo"`，编译器通常不能把这个表达式当作普通字面量拼接处理，拼接会在运行期产生新的字符串对象，所以：

```java
str1 == str3 // false
```

如果 `a` 是 `final` 且能在编译期确定：

```java
final String a = "llo";
String str3 = "he" + a;
```

则可能被编译期优化为 `"hello"`。

**考点：**

- 字符串字面量拼接
- 编译期常量
- 变量参与拼接
- 字符串常量池

**易错点：**

- 字面量拼接和变量拼接不是一回事
- `==` 判断引用，内容比较用 `equals()`

## Java-003 装箱与拆箱

**题目：**

装箱、拆箱操作发生在？

**选项：**

- A. 类与对象之间
- B. 对象与对象之间
- C. 引用类型与值类型之间
- D. 引用类型与引用类型之间

**正确答案：** C

**解析：**

装箱是基本数据类型转换为对应包装类：

```java
int x = 10;
Integer y = x; // 装箱
```

拆箱是包装类转换为基本数据类型：

```java
Integer y = 10;
int x = y; // 拆箱
```

基本数据类型也常被称为值类型，包装类属于引用类型，所以装箱、拆箱发生在基本类型和值对应的包装类型之间，也就是题目中的“引用类型与值类型之间”。

**考点：**

- 自动装箱
- 自动拆箱
- 基本类型与包装类

**易错点：**

- `Integer` 是对象，`int` 是基本类型
- 自动拆箱可能触发 `NullPointerException`

## Java-004 `String.toLowerCase()` 与引用比较

**题目：**

下面代码将输出什么内容？

```java
public class SystemUtil {
    public static boolean isAdmin(String userId) {
        return userId.toLowerCase() == "admin";
    }

    public static void main(String[] args) {
        System.out.println(isAdmin("Admin"));
    }
}
```

**选项：**

- A. `true`
- B. `false`
- C. `1`
- D. 编译错误

**正确答案：** B

**你的答案：** A

**解析：**

原文件解析：

在源码中 `toLowerCase` 是重新 `new String()`。

**原文件解析图片：**

![toLowerCase 源码解析](https://uploadfiles.nowcoder.com/images/20170314/184838_1489466288980_4A47A0DB6E60853DEDFCFDF08A5CA249)

所以 `==` 是比较对象是否是同一个对象，所以为 `false`。

`userId.toLowerCase()` 会返回一个字符串对象。对 `"Admin"` 调用 `toLowerCase()` 后，内容虽然变成了 `"admin"`，但它和字符串常量池中的字面量 `"admin"` 不一定是同一个对象。

`==` 比较的是引用是否指向同一个对象，不是比较内容，所以结果是：

```text
false
```

正确的内容比较写法应该是：

```java
return "admin".equals(userId.toLowerCase());
```

把常量写在前面还可以避免 `userId` 为 `null` 时调用 `equals()` 触发空指针。不过这段代码如果 `userId` 本身为 `null`，在 `toLowerCase()` 处仍会抛出 `NullPointerException`。

**考点：**

- `String.toLowerCase()`
- `==` 与 `equals()`
- 字符串内容比较

**易错点：**

- 字符串内容比较不要用 `==`

- 方法返回的新字符串对象，即使内容相同，也不代表引用相同​


## 今日 Java 总结

- 看到字符串比较，先判断是比较引用还是比较内容
- 纯字面量拼接可能在编译期合并
- 变量或 `new String()` 参与拼接时，通常是运行期新对象
- 装箱拆箱本质是基本类型和包装类之间的转换
