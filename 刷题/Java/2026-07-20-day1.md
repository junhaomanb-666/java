## Java-001 语句语法判断

**题目：**

下列哪个语句语法正确？

**选项：**

- A. `byte y = 11; byte x = y + y;`
- B. `String x = new Object();`
- C. `Object x = new String("Hellow");`
- D. `int a[11] = new int[11];`

**正确答案：** C

**你的答案：** 未记录

**解析：**

C 正确。`String` 是 `Object` 的子类，子类对象可以赋值给父类引用，属于向上转型。

A 错误。`byte + byte` 会自动提升为 `int`，不能直接赋值给 `byte`，需要强转：

```java
byte x = (byte) (y + y);
```

B 错误。`Object` 是父类，不能直接赋值给 `String` 类型变量。

D 错误。Java 数组声明不能在变量名后的方括号里写长度，正确写法是：

```java
int[] a = new int[11];
int a[] = new int[11];
```

**考点：**

- 自动类型提升
- 向上转型
- 数组声明语法

**易错点：**

- 小整数类型参与运算后结果通常提升为 `int`
- Java 数组长度写在 `new` 后面，不写在变量声明处

## Java-002 Java 7 基础类库与线程安全

**题目：**

在 Java 7 中，下列哪个说法是正确的？

**选项：**

- A. `ConcurrentHashMap` 使用 `synchronized` 关键字保证线程安全
- B. `HashMap` 实现了 `Collection` 接口
- C. `Arrays.asList()` 方法返回 `java.util.ArrayList` 对象
- D. `SimpleDateFormat` 对象是线程不安全的

**正确答案：** D

**你的答案：** A

**解析：**

D 正确。`SimpleDateFormat` 内部有可变状态，多线程共享同一个实例时可能导致解析或格式化错误。常见解决方式是每个线程创建独立实例，或使用 `ThreadLocal`，或改用 Java 8 的 `DateTimeFormatter`。

A 错误。Java 7 的 `ConcurrentHashMap` 主要通过分段锁 `Segment` 保证并发安全，`Segment` 继承自 `ReentrantLock`，不是简单依靠 `synchronized`。

B 错误。`HashMap` 实现的是 `Map` 接口，不是 `Collection` 接口。

C 错误。`Arrays.asList()` 返回的是 `java.util.Arrays$ArrayList`，不是常用的 `java.util.ArrayList`。

**考点：**

- Java 7 `ConcurrentHashMap` 分段锁
- `Map` 与 `Collection` 体系
- `Arrays.asList()` 返回值
- `SimpleDateFormat` 线程安全

**易错点：**

- Java 7 和 Java 8 的 `ConcurrentHashMap` 实现机制不同
- `HashMap` 不属于 `Collection` 子接口

## Java-003 `Arrays.asList()` 固定长度列表

**题目：**

下面 Java 代码的运行结果为？

```java
public static void main(String[] args) {
    List<String> list = Arrays.asList("A", "B", "C");
    list.add("D");
    System.out.println(list.get(3));
}
```

**选项：**

- A. `C`
- B. `D`
- C. 编译错误
- D. 运行错误

**正确答案：** D

**你的答案：** A

**解析：**

`Arrays.asList("A", "B", "C")` 返回固定长度的 `List`，底层是 `java.util.Arrays$ArrayList`，不是 `java.util.ArrayList`。它可以 `get()`、`set()`，但不能 `add()`、`remove()`。

执行到：

```java
list.add("D");
```

会抛出 `UnsupportedOperationException`，所以不会执行到 `list.get(3)`。

**可变列表写法：**

```java
List<String> list = new ArrayList<>(Arrays.asList("A", "B", "C"));
```

**考点：**

- `Arrays.asList()` 返回固定长度列表
- `UnsupportedOperationException`

**易错点：**

- 不是越界异常，因为 `get(3)` 根本不会执行
- 返回类型不是 `java.util.ArrayList`

## Java-004 NIO Channel 相比 Stream 的优势

**题目：**

以下哪些是 Java NIO 中 `Channel` 相比传统 IO `Stream` 的优势？

**选项：**

- A. `Channel` 支持双向读写，而 `Stream` 通常是单向的
- B. `Channel` 支持非阻塞模式
- C. `Channel` 可以直接与 `Buffer` 交互，支持 scatter/gather 操作
- D. `Channel` 在所有场景下的性能都优于 `Stream`

**正确答案：** A、B、C

**你的答案：** B、C、D

**解析：**

`Channel` 通常支持双向读写，例如 `SocketChannel`；支持非阻塞模式，配合 `Selector` 可以实现多路复用；并且 `Channel` 通过 `Buffer` 读写数据，支持分散读 `ScatteringByteChannel` 和聚集写 `GatheringByteChannel`。

D 错误。NIO 不是任何情况下都比传统 IO 更快。简单小文件顺序读写时，传统 IO 可能更简单，性能也可能足够甚至更好。

**考点：**

- NIO `Channel`
- 非阻塞 IO
- `Buffer`
- scatter/gather

**易错点：**

- 技术特性不能绝对化，看到“所有场景”要警惕

## Java-005 `while`、`do-while`、`for`

**题目：**

下列关于 `while` 循环、`do-while` 循环和 `for` 循环说法错误的是？

**选项：**

- A. `while` 循环先执行条件判断，`do-while` 循环执行循环体
- B. `do-while` 循环结束的条件是关键字 `while` 后的条件表达式成立
- C. `for` 循环结构中的 3 个表达式缺一不可
- D. `while` 循环能够实现的操作，`for` 循环也能实现

**正确答案：** B、C

**你的答案：** D

**解析：**

B 错误。`do-while` 后面的条件为 `true` 时继续循环，为 `false` 时结束循环。

C 错误。`for` 的三个表达式都可以省略，但两个分号不能省略：

```java
for (;;) {
}
```

A 正确。`while` 是先判断再执行，`do-while` 是先执行一次循环体再判断。

D 正确。`while` 和 `for` 都属于条件循环，通常可以互相转换。

**考点：**

- 三种循环结构
- `for (;;)` 无限循环

**易错点：**

- `do-while` 条件成立表示继续循环，不是结束循环
- `for` 的表达式可以省略，分号不能省略

## Java-006 继承与向上转型

**题目：**

A 派生出子类 B，B 派生出子类 C，并且在 Java 源代码中有如下声明：

```java
A a0 = new A();
A a1 = new B();
A a2 = new C();
```

问以下哪个说法是正确的？

**选项：**

- A. 只有第一行能通过编译
- B. 第 1、2 行能通过编译，但第 3 行编译出错
- C. 第 1、2、3 行能通过编译，但第 2、3 行运行时出错
- D. 第 1 行、第 2 行和第 3 行的声明都是正确的

**正确答案：** D

**你的答案：** B

**解析：**

如果继承关系是 `A <- B <- C`，那么 C 是 B 的子类，也是 A 的间接子类。

```java
A a0 = new A();
A a1 = new B();
A a2 = new C();
```

三行都正确。父类引用指向子类对象属于向上转型，不需要强制转换，也不会因为声明本身导致运行时错误。

**考点：**

- 继承传递性
- 向上转型
- 多态

**易错点：**

- “子类的子类”仍然是祖先类的子类
- 向上转型不需要强制转换

## Java-007 基本数据类型运算与赋值

**题目：**

Which lines of the following will produce an error?

```java
byte a1 = 2, a2 = 4, a3;
short s = 16;
a2 = s;
a3 = a1 * a2;
```

**选项：**

- A. Line 3 and Line 4
- B. Line 1 only
- C. Line 3 only
- D. Line 4 only

**正确答案：** A

**你的答案：** D

**解析：**

第 3 行错误：

```java
a2 = s;
```

`short` 不能直接赋值给 `byte`，因为 `short` 范围比 `byte` 大，可能发生精度损失，需要显式强转。

第 4 行错误：

```java
a3 = a1 * a2;
```

`byte` 参与算术运算时会自动提升为 `int`，所以 `a1 * a2` 的结果类型是 `int`，不能直接赋值给 `byte`。

**修正：**

```java
a2 = (byte) s;
a3 = (byte) (a1 * a2);
```

**考点：**

- 小整数类型自动提升
- 窄化类型转换必须显式强转

**易错点：**

- `byte`、`short`、`char` 参与普通算术运算时结果通常是 `int`
- 赋值转换和算术提升是两套规则

## Java-008 Java 方法参数传递

**题目：**

指出以下程序运行的结果是？

```java
public class Example {
    String str = new String("good");
    char[] ch = {'a', 'b', 'c'};

    public static void main(String[] args) {
        Example ex = new Example();
        ex.change(ex.str, ex.ch);
        System.out.print(ex.str + " and ");
        System.out.print(ex.ch);
    }

    public void change(String str, char[] ch) {
        str = "test ok";
        ch[0] = 'g';
    }
}
```

**选项：**

- A. `good and abc`
- B. `good and gbc`
- C. `test ok and abc`
- D. `test ok and gbc`

**正确答案：** B

**你的答案：** 未记录

**解析：**

Java 只有值传递。引用类型传递的是引用值的副本。

`str = "test ok";` 只是改变方法内部局部参数变量 `str` 的指向，不影响成员变量 `ex.str`，所以前半部分仍是 `good`。

`ch[0] = 'g';` 是通过引用副本修改同一个字符数组对象的内容，因此原数组从 `{'a','b','c'}` 变成 `{'g','b','c'}`。

`System.out.print(char[])` 会调用 `PrintStream` 对 `char[]` 的重载方法，直接打印字符数组内容，所以后半部分是 `gbc`。

**考点：**

- Java 只有值传递
- 引用类型传递的是引用值副本
- `String` 不可变
- 数组内容可变

**易错点：**

- “传地址”这种说法容易误导，准确说法是“传递引用值的副本”
- 改变参数变量指向，不等于修改原对象

## Java-009 Java 11 `HttpClient.sendAsync()`

**题目：**

以下代码使用 Java 的 `HttpClient`（Java 11+），关于其异步请求的实现，哪项是正确的？

```java
HttpClient client = HttpClient.newHttpClient();
HttpRequest request = HttpRequest.newBuilder()
        .uri(URI.create("https://api.example.com/data"))
        .build();
CompletableFuture<HttpResponse<String>> future =
        client.sendAsync(request, HttpResponse.BodyHandlers.ofString());
```

**选项：**

- A. `sendAsync` 默认使用与主线程相同的线程发送请求
- B. `sendAsync` 返回的 `CompletableFuture` 在请求完成前调用 `join()` 不会阻塞
- C. `HttpClient` 默认使用实现提供的默认 `executor` 来处理异步请求
- D. `sendAsync` 不支持 HTTP/2 协议

**正确答案：** C

**你的答案：** 未记录

**解析：**

`sendAsync()` 会异步发送请求，并立即返回：

```java
CompletableFuture<HttpResponse<String>>
```

没有指定自定义 `Executor` 时，异步任务由实现提供的默认执行器处理。

A 错误。异步请求不保证由调用它的主线程执行。

B 错误。`sendAsync()` 本身通常很快返回，但如果请求尚未完成，调用 `future.join()` 会阻塞当前线程等待结果。

D 错误。Java 11 `HttpClient` 支持 HTTP/1.1 和 HTTP/2，默认优先 HTTP/2。

**考点：**

- Java 11 `HttpClient`
- `send()` 与 `sendAsync()`
- `CompletableFuture`
- 默认执行器

**易错点：**

- 异步方法返回快，不代表后续 `join()` 不阻塞
- `sendAsync()` 支持 HTTP/2
