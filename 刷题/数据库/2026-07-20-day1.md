## DB-001 MySQL 视图的作用

**题目：**

下列选项中关于 MySQL 视图的说法正确的有？

**选项：**

- A. 使用视图可以达到保护数据的作用，用户只能访问他们被允许查询的结果集
- B. 视图可以简化复杂的 SQL 操作，用户不需要关心表的结构、关联条件和筛选条件
- C. 视图创建之后，可以对它进行 SELECT 操作，但不能对它插入、修改、删除操作
- D. 保障数据安全性，提高查询效率是视图的主要作用

**正确答案：** A、B、D

**你的答案：** A、B

**解析：**

视图是基于查询结果定义的虚拟表。它可以隐藏底层表结构和部分字段，从而实现一定的数据访问控制；也可以封装复杂 SQL，让使用者不必每次都写复杂的关联条件和筛选条件。

C 错在过于绝对。视图不是一定不能增删改，满足条件的简单视图可以执行插入、更新、删除。

D 按题库答案归为正确，强调视图有安全性和封装查询的作用。但实际开发里要注意：视图并不天然提升查询性能，复杂视图仍可能执行复杂底层 SQL。

**考点：**

- 视图是虚拟表
- 视图可以做权限隔离和 SQL 封装
- 视图是否可更新取决于定义是否满足条件

**易错点：**

- 不要绝对认为视图不能增删改
- 不要把视图等同于性能优化手段

## DB-002 MySQL 查询语句逻辑执行顺序

**题目：**

下面哪一个是 MySQL 查询语句的正确执行顺序？

**选项：**

- A. `SELECT -> FROM(including JOINs) -> WHERE -> GROUP BY -> HAVING -> DISTINCT -> ORDER BY -> LIMIT/OFFSET`
- B. `SELECT -> DISTINCT -> FROM(including JOINs) -> WHERE -> GROUP BY -> HAVING -> ORDER BY -> LIMIT/OFFSET`
- C. `FROM(including JOINs) -> WHERE -> GROUP BY -> HAVING -> SELECT -> DISTINCT -> ORDER BY -> LIMIT/OFFSET`
- D. `FROM(including JOINs) -> WHERE -> GROUP BY -> HAVING -> DISTINCT -> SELECT -> ORDER BY -> LIMIT/OFFSET`

**正确答案：** C

**你的答案：** B

**解析：**

SQL 的书写顺序通常以 `SELECT` 开头，但逻辑执行顺序不是。数据库先确定数据来源，再做行过滤、分组、分组过滤，然后才计算查询列、去重、排序、限制返回数量。

必须背熟：

```sql
FROM / JOIN
WHERE
GROUP BY
HAVING
SELECT
DISTINCT
ORDER BY
LIMIT / OFFSET
```

**考点：**

- SQL 书写顺序和逻辑执行顺序不同
- `WHERE` 过滤行
- `HAVING` 过滤分组

**易错点：**

- `SELECT` 不是第一步
- `ORDER BY` 靠后执行

## DB-003 SQL 字段别名写法

**题目：**

下列选项中使用别名的方法不正确的是？

**选项：**

- A. `字段名称=别名`
- B. `字段名称 AS 别名`
- C. `字段名称 别名`
- D. `别名=字段名称`

**正确答案：** A

**你的答案：** D

**解析：**

MySQL 中字段别名常用 `AS` 或空格：

```sql
SELECT 字段名称 AS 别名 FROM 表名;
SELECT 字段名称 别名 FROM 表名;
```

`字段名称=别名` 更像比较表达式，不是常规字段别名写法。`别名=字段名称` 在某些 SQL 方言中可能出现，但 MySQL 推荐使用 `AS` 或空格写法。

**考点：**

- MySQL 字段别名
- `AS` 可以省略

**易错点：**

- `字段名 别名` 中间是空格
- 最稳妥写法是 `字段名 AS 别名`
