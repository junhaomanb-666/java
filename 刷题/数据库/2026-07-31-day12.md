## 题目 1：哪些字段适合建立索引？

哪些字段适合建立索引？

A. 在 `SELECT` 子句中的字段  
B. 外键字段  
C. 主键字段  
D. 在 `WHERE` 子句中的字段

正确答案：BCD

原解析：

B 外键字段适合经常用于关联查询，建立索引可提高 `JOIN` 效率；C 主键字段适合，主键会自动创建主键索引；D `WHERE` 子句中的字段适合，经常作为查询条件，可以加快数据筛选。

补充解析：

索引适合建立在经常参与查找、连接、排序、分组的字段上。单纯出现在 `SELECT` 结果列表中的字段，不一定能帮助数据库定位数据，因此 A 不是充分理由。

记忆点：主键、外键、高频 `WHERE` 条件字段优先考虑索引。

## 题目 2：当前事务约束模式设置

下列哪个 SQL 语句用于对当前事务设置约束模式？

A. `SET TRANSACTION`  
B. `SET CONSTRAINTS`  
C. `SERIALIZABLE`  
D. `IMMEDIATE`

正确答案：B  
你的答案：C

原解析：

在某些情况下，并不希望每个 SQL 语句执行后立即进行完整性约束检查，而会延迟到事务提交时进行完整性约束检查，因此可以对当前事务设置约束模式，通常可以使用 `SET CONSTRAINTS` 对当前事务设置约束模式，并且主要是 `INITIALLY IMMEDIATE` 或者 `INITIALLY DEFERRED` 模式，故 B 项正确。A 项的 `SET TRANSACTION` 是设置事务的操作；C 项的 `SERIALIZABLE` 是数据库隔离级别的一个选项，设置为此选项可以避免幻读；D 项是约束模式的一种类型。

补充解析：

这题容易把“事务隔离级别”和“约束检查时机”混在一起。

- `SET CONSTRAINTS`：设置当前事务中约束检查是立即检查还是延迟检查。
- `SERIALIZABLE`：事务隔离级别，不是约束模式设置语句。
- `IMMEDIATE`：约束检查模式的状态值，不是完整语句。

记忆点：看到“约束模式、延迟到提交时检查”，优先想 `SET CONSTRAINTS`。

## 题目 3：MySQL 模拟 FULL JOIN

MySQL 版本 8.0.25 中表 `student_table`：

```sql
CREATE TABLE `student_table` (
  `id` int(11) unsigned NOT NULL AUTO_INCREMENT,
  `name` varchar(11) COLLATE utf8mb4_unicode_ci DEFAULT NULL,
  `birth` varchar(11) COLLATE utf8mb4_unicode_ci DEFAULT NULL,
  `sex` char(1) COLLATE utf8mb4_unicode_ci DEFAULT NULL,
  PRIMARY KEY (`id`)
) ENGINE=InnoDB AUTO_INCREMENT=0 DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;
```

插入如下记录：

| id | name | birth | sex |
| --- | --- | --- | --- |
| 1004 | 张三 | 2000-08-06 | 男 |
| 1006 | 王五 | 2000-08-06 | 女 |
| 1008 | 张三 | 2002-12-01 | 女 |
| 1009 | 李四 | 2000-01-01 | 男 |
| 1010 | 李四 | 2001-01-01 | 男 |
| 1011 | 李四 | 2002-08-06 | 女 |
| 1012 | 张三 | 2001-12-01 | 女 |
| 1013 | 赵六 | 2000-09-06 | 男 |

现有 SQL：

```sql
SELECT t1.*, t2.*
FROM (SELECT * FROM student_table WHERE sex = '男') t1
FULL JOIN (SELECT * FROM student_table WHERE sex = '女') t2
  ON t1.name = t2.name;
```

问：如下 SQL 中与上述 SQL 实现的语义和结果一致的是哪些？

### 选项 A

```sql
SELECT t1.*, t2.*
FROM (SELECT * FROM student_table WHERE sex = '男') t1
RIGHT JOIN (SELECT * FROM student_table WHERE sex = '女') t2
  ON t1.name = t2.name
 AND t1.name IS NULL
UNION ALL
SELECT t1.*, t2.*
FROM (SELECT * FROM student_table WHERE sex = '男') t1
LEFT JOIN (SELECT * FROM student_table WHERE sex = '女') t2
  ON t1.name = t2.name;
```

### 选项 B

```sql
SELECT t1.*, t2.*
FROM (SELECT * FROM student_table WHERE sex = '男') t1
RIGHT JOIN (SELECT * FROM student_table WHERE sex = '女') t2
  ON t1.name = t2.name
WHERE t1.name IS NULL
UNION ALL
SELECT t1.*, t2.*
FROM (SELECT * FROM student_table WHERE sex = '男') t1
LEFT JOIN (SELECT * FROM student_table WHERE sex = '女') t2
  ON t1.name = t2.name;
```

### 选项 C

```sql
SELECT t1.*, t2.*
FROM (SELECT * FROM student_table WHERE sex = '男') t1
RIGHT JOIN (SELECT * FROM student_table WHERE sex = '女') t2
  ON t1.name = t2.name
UNION ALL
SELECT t1.*, t2.*
FROM (SELECT * FROM student_table WHERE sex = '男') t1
LEFT JOIN (SELECT * FROM student_table WHERE sex = '女') t2
  ON t1.name = t2.name
WHERE t2.name IS NULL;
```

### 选项 D

```sql
SELECT t1.*, t2.*
FROM (SELECT * FROM student_table WHERE sex = '男') t1
RIGHT JOIN (SELECT * FROM student_table WHERE sex = '女') t2
  ON t1.name = t2.name
UNION ALL
SELECT t1.*, t2.*
FROM (SELECT * FROM student_table WHERE sex = '男') t1
LEFT JOIN (SELECT * FROM student_table WHERE sex = '女') t2
  ON t1.name = t2.name
 AND t2.name IS NULL;
```

正确答案：B、C

原解析：

为方便阅读，只展示：

```text
男生ID、男生姓名 | 女生ID、女生姓名
```

实际查询还会输出 `birth`、`sex`。

先确定目标 `FULL JOIN` 应该得到什么。

男生数据：

| ID | 姓名 |
| --- | --- |
| 1004 | 张三 |
| 1009 | 李四 |
| 1010 | 李四 |
| 1013 | 赵六 |

女生数据：

| ID | 姓名 |
| --- | --- |
| 1006 | 王五 |
| 1008 | 张三 |
| 1011 | 李四 |
| 1012 | 张三 |

连接条件：

```sql
ON t1.name = t2.name
```

张三：男生有 1 个张三，女生有 2 个张三，所以 `1 * 2 = 2` 条。

| 男生ID | 男生姓名 | 女生ID | 女生姓名 |
| --- | --- | --- | --- |
| 1004 | 张三 | 1008 | 张三 |
| 1004 | 张三 | 1012 | 张三 |

李四：男生有 2 个李四，女生有 1 个李四，所以 `2 * 1 = 2` 条。

| 男生ID | 男生姓名 | 女生ID | 女生姓名 |
| --- | --- | --- | --- |
| 1009 | 李四 | 1011 | 李四 |
| 1010 | 李四 | 1011 | 李四 |

没有匹配的人：男生赵六没有对应女生；女生王五没有对应男生。

所以完整的 `FULL JOIN` 应有 6 条：

| 男生ID | 男生姓名 | 女生ID | 女生姓名 |
| --- | --- | --- | --- |
| 1004 | 张三 | 1008 | 张三 |
| 1004 | 张三 | 1012 | 张三 |
| 1009 | 李四 | 1011 | 李四 |
| 1010 | 李四 | 1011 | 李四 |
| 1013 | 赵六 | `NULL` | `NULL` |
| `NULL` | `NULL` | 1006 | 王五 |

结果顺序没有 `ORDER BY`，因此不保证。

选项 A：第一部分的 `ON t1.name = t2.name AND t1.name IS NULL` 要求男生姓名既等于女生姓名，又必须为 `NULL`。但男生姓名都不为 `NULL`，所以一条都匹配不上。因为是 `RIGHT JOIN`，所有女生都会被保留，共 4 条。第二部分普通 `LEFT JOIN` 得到 5 条。A 最终 `4 + 5 = 9` 条，张三、李四的女生记录既以“不匹配行”出现，又以正常匹配行出现，错误。

选项 B：先正常执行 `RIGHT JOIN`，再用 `WHERE t1.name IS NULL` 只保留“女生存在、男生不存在”的数据，只有王五，共 1 条。第二部分普通 `LEFT JOIN` 得到 5 条。B 最终 `1 + 5 = 6` 条，正确。

选项 C：第一部分完整 `RIGHT JOIN` 得到“匹配的数据 + 女表独有的王五”，共 5 条。第二部分普通 `LEFT JOIN` 后，用 `WHERE t2.name IS NULL` 只保留“男生存在、女生不存在”的数据，只有赵六，共 1 条。C 最终 `5 + 1 = 6` 条，正确。

选项 D：第二部分的 `ON t1.name = t2.name AND t2.name IS NULL` 要求女生姓名既等于男生姓名，又必须是 `NULL`。题目中女生姓名都不为 `NULL`，所以所有男生都匹配失败。因为是 `LEFT JOIN`，全部男生仍会保留，共 4 条。D 最终 `5 + 4 = 9` 条，张三和李四被错误地当成未匹配男生，错误。

最后对比：

| 选项 | 第一部分 | 第二部分 | 总行数 | 判断 |
| --- | --- | --- | --- | --- |
| A | 所有女生都被当成未匹配 | 完整左连接 | 9 | 错 |
| B | 只取右表独有的王五 | 完整左连接 | 6 | 对 |
| C | 完整右连接 | 只取左表独有的赵六 | 6 | 对 |
| D | 完整右连接 | 所有男生都被当成未匹配 | 9 | 错 |

最关键区别：

```sql
LEFT JOIN ...
WHERE 右表字段 IS NULL
```

是在连接完成后筛选真正未匹配的行；而：

```sql
LEFT JOIN ...
ON 匹配条件 AND 右表字段 IS NULL
```

会改变连接条件，导致原本能匹配的数据也无法匹配。

补充解析：

MySQL 不直接支持 `FULL JOIN`，常见模拟方式是：

```sql
LEFT JOIN
UNION ALL
RIGHT JOIN 中左表未匹配的部分
```

或者反过来：

```sql
RIGHT JOIN
UNION ALL
LEFT JOIN 中右表未匹配的部分
```

判断这类题时，一定盯住 `IS NULL` 出现的位置：写在 `WHERE` 是筛未匹配行；写在 `ON` 是改连接条件。
