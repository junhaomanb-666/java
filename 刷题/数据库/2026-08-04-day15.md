## 题目 1：统计不重复姓名总数

MySQL 中表 `student_table(id, name, birth, sex)`，查询姓名总数，重复的名字只算一次，错误的是？

A.

```sql
SELECT COUNT(DISTINCT name)
FROM student_table;
```

B.

```sql
SELECT COUNT(name)
FROM (
  SELECT DISTINCT name
  FROM student_table
) t1;
```

C.

```sql
SELECT COUNT(name)
FROM (
  SELECT name, COUNT(*) AS c1
  FROM student_table
  GROUP BY name
  HAVING c1 > 1
) t1;
```

D.

```sql
SELECT COUNT(name)
FROM (
  SELECT name
  FROM student_table
  GROUP BY name
) t1;
```

正确答案：C

原解析：

如果写成 `c1 = 1` 才是统计只出现一次的姓名；本题要求“重复的名字只算一次”，应该统计去重后的姓名数量，而不是只统计出现次数大于 1 的姓名。

补充解析：

题目要的是“姓名种类数”，也就是去重计数。

- A：`COUNT(DISTINCT name)`，直接统计不同姓名数量，正确。
- B：先 `DISTINCT name` 去重，再统计，正确。
- D：`GROUP BY name` 后每个姓名一组，再统计组数，正确。
- C：`HAVING c1 > 1` 只保留重复出现过的姓名，会漏掉只出现一次的姓名，所以错误。

记忆点：`COUNT(DISTINCT col)` 等价于“先去重，再计数”。

## 题目 2：SQL 逻辑执行顺序

纯知识点：SQL 执行顺序。

知识点图：

![SQL执行顺序](../解析图片/day15/1785838931066.png)

文字整理：

```text
1. FROM
2. ON
3. JOIN
4. WHERE
5. GROUP BY
6. HAVING + 聚合函数
7. SELECT
8. ORDER BY
9. LIMIT
```

补充解析：

这里说的是 SQL 的逻辑执行顺序，不是数据库优化器真实物理执行顺序。刷题时按逻辑顺序判断即可：

- `WHERE` 在分组前执行，所以不能直接使用聚合函数筛选。
- `HAVING` 在分组后执行，所以可以筛选聚合结果。
- `SELECT` 逻辑上比 `WHERE` 晚，所以很多数据库中 `WHERE` 不能直接使用 `SELECT` 里的别名。
- `ORDER BY` 靠后，所以通常可以使用 `SELECT` 中的别名。

记忆点：先定表，再连接，再过滤，再分组，再筛聚合，再选列，再排序分页。

## 题目 3：更新最后登录时间避免覆盖

需要更新用户最后登录时间，但要避免更新时间被其他事务覆盖，应该使用？

A. `COMMIT`  
B. `FOR UPDATE`  
C. `CHECK CONSTRAINT`  
D. `AUTO_INCREMENT`

正确答案：B

原解析：

`FOR UPDATE` 是 SQL 的锁定机制，在事务中锁定选中行直到提交，能有效避免覆盖。

补充解析：

`SELECT ... FOR UPDATE` 会对查询到的行加排他锁，常用于“先查后改”的事务场景。例如：

```sql
START TRANSACTION;

SELECT last_login_time
FROM user
WHERE id = 1
FOR UPDATE;

UPDATE user
SET last_login_time = NOW()
WHERE id = 1;

COMMIT;
```

在事务提交前，其他事务不能随意修改这行数据，从而避免并发覆盖。

记忆点：涉及“事务中先读后改、防止别人改同一行”，优先想 `FOR UPDATE`。

## 题目 4：事务控制语句

下列关于事务控制语句的描述说法错误的是？

A. `ROLLBACK` 代表回滚，其会结束用户的事务，并撤销正在进行的所有未提交的修改。  
B. `SAVEPOINT identifier` 代表 `SAVEPOINT` 允许在事务中创建一个保存点，一个事务中可以有多个 `SAVEPOINT`。  
C. `COMMIT WORK` 可以提交事务，并使得已对数据库做的所有修改成为永久性。  
D. `RELEASE SAVEPOINT identifier` 则是用来回滚到指定的 `SAVEPOINT`，并撤销所有 `DELETE` 的工作。

正确答案：D  
你的答案：C

原解析：

`RELEASE SAVEPOINT identifier` 的主要作用是删除一个保存点，但它不会自动撤销该保存点之后执行的操作。如果想撤销操作，需要使用 `ROLLBACK TO SAVEPOINT identifier`。

补充解析：

几个事务控制语句要分清：

- `COMMIT` / `COMMIT WORK`：提交事务，让修改永久生效。
- `ROLLBACK`：回滚整个事务，撤销未提交修改。
- `SAVEPOINT name`：在事务内部创建保存点。
- `ROLLBACK TO SAVEPOINT name`：回滚到某个保存点。
- `RELEASE SAVEPOINT name`：删除保存点，不负责撤销修改。

记忆点：`RELEASE` 是释放保存点；真正撤销要看 `ROLLBACK`。
