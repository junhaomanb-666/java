## DB-001 `ROW_NUMBER()` 窗口函数

**题目：**

使用窗口函数 `ROW_NUMBER() OVER (PARTITION BY dept_id ORDER BY salary DESC)` 时，以下描述错误的是？

**选项：**

- A. 相同 `salary` 值的行会获得不同序号
- B. 不同 `dept_id` 的分区各自独立排序
- C. `ORDER BY` 子句缺失会导致语法错误
- D. 结果集中每个分区的序号从 1 开始

**正确答案：** C

**你的答案：** B

**解析：**

`PARTITION BY dept_id` 会按部门分区，不同部门之间独立编号和排序，所以 B 正确。

`ROW_NUMBER()` 会给每一行分配唯一序号，即使 `salary` 相同，也会得到不同序号，所以 A 正确。

D 正确，每个分区都从 1 开始编号。

C 错在“语法错误”。`ORDER BY` 缺失会导致排序行为不确定，但通常不是语法错误。没有明确排序条件时，数据库无法保证行号分配顺序稳定。

**考点：**

- 窗口函数
- `PARTITION BY`
- `ORDER BY`
- `ROW_NUMBER()`

**易错点：**

- `PARTITION BY` 是分组编号，不是普通 `GROUP BY`
- 没有 `ORDER BY` 更多是结果不稳定，不一定语法错误

## DB-002 `ROUND()` 与 `TRUNCATE()`

**题目：**

下列函数语句得不到相同数值结果的选项是？

**选项：**

- A. `SELECT ROUND(2.35)`
- B. `SELECT ROUND(1.96, 1)`
- C. `SELECT TRUNCATE(1.99, 1)`
- D. `SELECT TRUNCATE(2.83, 0)`

**正确答案：** C

**你的答案：** A

**解析：**

`ROUND()` 是四舍五入，`TRUNCATE()` 是按指定小数位直接截断。

逐项计算：

```sql
ROUND(2.35)       -- 2
ROUND(1.96, 1)    -- 2.0
TRUNCATE(1.99, 1) -- 1.9
TRUNCATE(2.83, 0) -- 2
```

A、B、D 的数值结果都可以视为 2，C 的结果是 1.9，所以 C 得不到相同数值结果。

**考点：**

- `ROUND()` 四舍五入
- `TRUNCATE()` 截断

**易错点：**

- `TRUNCATE()` 不四舍五入
- `ROUND(2.35)` 没指定小数位时返回整数

## DB-003 数据修改与锁模式

**题目：**

下列选项中的锁模式，可以用于数据修改操作，确保不会同时对同一资源进行多重更新的是？

**选项：**

- A. 共享锁
- B. 更新锁
- C. 排他锁
- D. 架构锁

**正确答案：** C

**你的答案：** B

**解析：**

排他锁，也叫独占锁，用于数据修改操作。加了排他锁后，其他事务通常不能读也不能写该资源，从而避免同一资源被并发多重更新。

共享锁允许其他事务读取，但不允许修改，常用于读操作。

更新锁用于 SQL Server 准备更新数据的阶段，之后会转换为排他锁。它可以降低死锁概率，但真正执行修改并保证独占的是排他锁。

架构锁用于依赖表结构的操作，例如架构稳定性锁和架构修改锁。

**考点：**

- 共享锁 S
- 排他锁 X
- 更新锁 U
- 架构锁

**易错点：**

- “准备更新”想到更新锁，但“确保不会多重更新”最终看排他锁

## DB-004 MySQL `INSERT` 语句

**题目：**

MySQL 中表 `student_info(id, name, birth, sex)`，字段类型都是 `varchar`，插入记录 `('1014', '张三', '2002-01-06', '男')`，SQL 错误的是？

**选项：**

- A. `insert into student_info values('1014', '张三', '2002-01-06', '男');`
- B. `insert into table student_info values('1014', '张三', '2002-01-06', '男');`
- C. `insert into student_info(id,name,birth,sex) values('1014', '张三', '2002-01-06', '男');`
- D. `insert into student_info(id,name,sex,birth) values('1014', '张三', '男','2002-01-06');`

**正确答案：** B

**你的答案：** A

**解析：**

MySQL 插入语句没有 `insert into table 表名` 这种写法，`table` 多余，所以 B 错。

A 是全字段插入，值的数量和表字段顺序一致，正确。

C 指定字段插入，字段和值一一对应，正确。

D 指定字段顺序为 `id,name,sex,birth`，值也按这个顺序提供，正确。

**常用写法：**

```sql
INSERT INTO table_name VALUES (value1, value2, ...);
INSERT INTO table_name (column1, column2) VALUES (value1, value2);
INSERT INTO table_name (column1, column2) VALUES (v1, v2), (v3, v4);
INSERT INTO table_name SELECT * FROM table_name2;
```

**考点：**

- `INSERT INTO`
- 全字段插入
- 指定字段插入

**易错点：**

- `INSERT INTO` 后直接跟表名，不写 `table`
- 指定字段插入时，值按指定字段顺序匹配

## DB-005 子查询与平均值比较

**题目：**

开发者需要找出所有订单金额高于平均值的用户。以下查询中，哪个能高效返回正确结果而不导致错误？

**选项：**

- A. `SELECT user_id FROM orders WHERE amount > AVG(amount)`
- B. `SELECT user_id FROM orders WHERE amount > (SELECT AVG(amount) FROM orders)`
- C. `SELECT user_id FROM orders GROUP BY user_id HAVING AVG(amount) > amount`
- D. `SELECT user_id, AVG(amount) FROM orders GROUP BY user_id HAVING amount > AVG(amount)`

**正确答案：** B

**你的答案：** D

**解析：**

题目要求比较“每一笔订单金额”和“所有订单的平均金额”。应先用子查询计算整体平均值：

```sql
SELECT AVG(amount)
FROM orders;
```

再在外层用 `WHERE` 逐行筛选：

```sql
SELECT user_id
FROM orders
WHERE amount > (
    SELECT AVG(amount)
    FROM orders
);
```

A 错误，聚合函数不能直接写在 `WHERE` 中做逐行过滤。

C、D 错误，`GROUP BY user_id` 后的 `amount` 既不是分组字段，也不是聚合结果，语义不明确，且逻辑变成了按用户分组后的比较。

**考点：**

- 子查询
- 聚合函数
- `WHERE` 与 `HAVING`

**易错点：**

- 聚合函数不能直接放在 `WHERE` 里比较
- 分组后不能随便使用非分组、非聚合字段

## DB-006 `UPDATE` 语句中的子查询

**题目：**

在 SQL 的 `UPDATE` 语句中，子查询可以被合法应用于哪些部分？

**选项：**

- A. 仅在 `WHERE` 子句
- B. 仅在 `SET` 子句
- C. 在 `SET` 子句或 `WHERE` 子句
- D. `UPDATE` 语句不允许使用子查询

**正确答案：** C

**你的答案：** 未记录

**解析：**

`UPDATE` 中子查询既可以用于 `WHERE` 条件筛选，也可以用于 `SET` 赋值。

示例：

```sql
UPDATE employees
SET salary = (SELECT AVG(salary) FROM employees)
WHERE dept_id IN (SELECT id FROM departments WHERE name = '研发部');
```

其中 `SET` 中的子查询用于计算新值，`WHERE` 中的子查询用于确定更新范围。

**考点：**

- `UPDATE`
- 子查询位置
- `SET` 与 `WHERE`

**易错点：**

- 不要只记得 `WHERE` 可以写子查询
- `SET` 中也可以用子查询计算更新值
