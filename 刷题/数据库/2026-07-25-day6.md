## DB-001 添加货币类型字段

**题目：**

为职员表添加列，列名为年末奖金，允许为空值，数据类型为货币数据类型。下列 SQL 语句正确的是？

**选项：**

- A. `ALTER TABLE 职员 ADD 年末奖金 NULL`
- B. `ALTER TABLE 职员 ADD 年末奖金 Money NULL`
- C. `ALTER TABLE 职员 ADD 年末奖金 Money NOT NULL`
- D. `ALTER TABLE 职员 ADD 年末奖金 INT NULL`

**正确答案：** B

**你的答案：** A

**解析：**

题目要求新增字段“年末奖金”，允许为空，且数据类型为货币类型。因此需要同时写出字段名、货币类型和 `NULL`：

```sql
ALTER TABLE 职员 ADD 年末奖金 Money NULL;
```

A 缺少数据类型。C 不允许为空，和题意不符。D 使用 `INT`，不是货币数据类型。

**考点：**

- `ALTER TABLE ... ADD`
- 货币类型
- `NULL` / `NOT NULL`

**易错点：**

- 添加列必须指定数据类型
- 题目要求允许为空，不能写 `NOT NULL`

**原文件解析：**

货币的字段类型一般有 `int`、`float`、`money/smallmoney`、`decimal/numeric`。

根据存储数据的精度不同选择：`int` 只能存储整数的钱；`money/smallmoney` 数据类型精确到它们所代表的货币单位的万分之一；`decimal/numeric` 可以自定义小数位和能存储的数据精度，所以一般使用这种类型的人会多一些。

## DB-002 数据库列级权限

**题目：**

某 IT 公司人事管理采用专门的人事管理系统来实现。后台数据库为 LF。新来的人事部张经理新官上任，第一件事是要对公司的员工做全面了解。可是在访问员工信息表 `EMPL` 里的工资和奖金字段时被拒绝，只能查看该表其他字段。作为 LF 的开发者你将如何解决这一问题？

**原文件解析图片：**

![列级权限解析](https://uploadfiles.nowcoder.com/images/20200828/619044738_1598587914444_4DE69893BC5DECA766485F5B397A6AC7)

**选项：**

- A. 废除张经理的数据库用户账户对表 `EMPL` 里的工资列和奖金列的 `SELECT` 权限
- B. 添加张经理到 `db_datareader` 角色
- C. 添加张经理到 `db_accessadmin` 角色
- D. 授予张经理的数据库用户账户对表 `EMPL` 里的工资列和奖金列的 `SELECT` 权限

**正确答案：** D

**你的答案：** C

**解析：**

题目中张经理能访问表中其他字段，但访问工资和奖金字段被拒绝，说明问题是列级权限不足。应直接授予其对 `EMPL` 表工资列和奖金列的 `SELECT` 权限。

A 是撤销权限，方向相反。

B `db_datareader` 角色通常给数据库中所有用户表的读取权限，权限过大，不符合只补工资和奖金列权限的最小授权原则。

C `db_accessadmin` 主要用于管理数据库访问权限，不是解决某几列读取权限的直接方式。

**考点：**

- 列级权限
- `SELECT` 权限
- 最小权限原则

**易错点：**

- 不要用过大的角色权限解决局部列权限问题
- 被拒绝哪个字段，就优先补哪个字段的权限

## DB-003 MySQL 模拟 `FULL JOIN`

**题目：**

MySQL 8.0.25 中表 `student_table(id,name,birth,sex)`，插入若干学生记录。现有 SQL：

**原文件解析图片：**

![FULL JOIN 解析](https://uploadfiles.nowcoder.com/images/20220617/993004961_1655456516680/14FC7E3CA734E29DCD649D849AC8509F)

```sql
select t1.*, t2.*
from (
    select * from student_table where sex = '男'
) t1
full join
(
    select * from student_table where sex = '女'
) t2
on t1.name = t2.name
```

问：如下 SQL 中与上述 SQL 实现的语义和结果一致的是？

**选项：**

原截图未保留完整 A/B/C/D 选项；根据文件中保留的解析，正确思路为使用 `INNER JOIN + LEFT JOIN 未匹配 + RIGHT JOIN 未匹配` 并用 `UNION ALL` 合并。

**正确答案：**

```sql
select t1.*, t2.*
from (
    select * from student_table where sex = '男'
) t1
inner join
(
    select * from student_table where sex = '女'
) t2
on t1.name = t2.name

union all

select t1.*, t2.*
from (
    select * from student_table where sex = '男'
) t1
left join
(
    select * from student_table where sex = '女'
) t2
on t1.name = t2.name
where t2.name is null

union all

select t1.*, t2.*
from (
    select * from student_table where sex = '男'
) t1
right join
(
    select * from student_table where sex = '女'
) t2
on t1.name = t2.name
where t1.name is null;
```

**你的答案：** 未记录

**解析：**

`FULL JOIN` 的结果可以拆成三部分：

1. 左右两表匹配成功的数据
2. 左表有、右表没有匹配的数据
3. 右表有、左表没有匹配的数据

MySQL 不直接支持标准 `FULL JOIN`，所以可以用：

```text
INNER JOIN
UNION ALL
LEFT JOIN ... WHERE 右表字段 IS NULL
UNION ALL
RIGHT JOIN ... WHERE 左表字段 IS NULL
```

来模拟完整外连接。

**考点：**

- `FULL JOIN`
- `INNER JOIN`
- `LEFT JOIN`
- `RIGHT JOIN`
- `UNION ALL`

**易错点：**

- MySQL 不直接支持标准 `FULL JOIN`
- 模拟完整外连接时，要同时保留左右两边未匹配的数据

**原文件解析：**

原文件中给出的实现：

```sql
select t1.*,t2.*
from (
select * from student_table where sex = '男' ) t1
inner join
(select * from student_table where sex = '女')t2
on t1.name = t2.name
union all
select t1.*,t2.*
from (
select * from student_table where sex = '男' ) t1
left join
(select * from student_table where sex = '女')t2
on t1.name = t2.name
where t2.name is null
union all
select t1.*,t2.*
from (
select * from student_table where sex = '男' ) t1
right join
(select * from student_table where sex = '女')t2
on t1.name = t2.name
where t1.name is null ;
```

`FULL JOIN = 匹配成功的数据 + 左表未匹配的数据 + 右表未匹配的数据`。

因此应该写成：

```sql
INNER JOIN
UNION ALL
LEFT JOIN ... WHERE 右表字段 IS NULL
UNION ALL
RIGHT JOIN ... WHERE 左表字段 IS NULL
```
