# JVM GC 专题整理

## 1. Java GC 是什么？

**通俗理解：** GC 就是 JVM 自带的“内存清理工”。Java 程序不断创建对象，对象不用了以后，不需要我们手动释放，JVM 会在合适时机把它们占用的堆内存回收掉。

**专业回答：** GC 是 Garbage Collection，即垃圾回收。它负责自动识别不再被引用的对象，并回收这些对象占用的内存。Java GC 主要工作在堆内存中，核心流程包括：判断对象是否存活、选择合适的回收算法、执行垃圾回收、必要时整理内存碎片。现代 JVM 通常使用可达性分析判断对象是否存活。

**记忆版：** GC = 自动回收不用的堆对象；核心是“判断存活 + 回收内存”。

## 2. JVM 堆空间通常怎么划分？

**通俗理解：** 堆可以理解成对象住的房子。新对象一般先进“新生代”，活得久的对象慢慢搬到“老年代”。这样 JVM 可以针对不同年龄的对象使用不同回收策略。

**专业回答：** HotSpot 虚拟机的堆通常按分代思想划分为新生代和老年代。新生代又分为 Eden、Survivor From、Survivor To 三个区域，常见比例是 `8:1:1`。大多数对象先分配到 Eden，经历 Minor GC 后仍然存活的对象会进入 Survivor 区，并随着年龄增长最终晋升到老年代。JDK 8 以后永久代被元空间替代，类元数据主要存放在本地内存中的 Metaspace。

**记忆版：** 堆 = 新生代 + 老年代；新生代 = Eden + S0 + S1；对象先年轻，活久进老年。

## 3. 对象一般如何分配内存？

**通俗理解：** 普通对象一般先放 Eden；Eden 放不下就触发一次新生代 GC；如果对象太大，可能直接放进老年代。

**专业回答：** 大多数对象优先在 Eden 区分配。当 Eden 空间不足时，会触发 Minor GC。存活对象会被复制到 Survivor 区，年龄增加；达到晋升阈值或 Survivor 空间不足时，进入老年代。大对象因为需要连续内存，可能直接进入老年代，避免在新生代频繁复制。长期存活对象也会逐步晋升到老年代。

**记忆版：** 普通对象进 Eden；放不下 Minor GC；活得久或太大进老年代。

## 4. 什么是 Minor GC、Major GC、Mixed GC、Full GC？

**通俗理解：** Minor GC 清理年轻对象，通常比较频繁；Full GC 清理范围更大，成本高，应该尽量减少。

**专业回答：** Minor GC 指发生在新生代的垃圾回收，触发频繁但速度通常较快。Major GC/Old GC 通常指老年代回收。Mixed GC 是 G1 收集器中的概念，会回收整个新生代以及部分老年代 Region。Full GC 通常会回收整个 Java 堆以及方法区/元空间相关资源，往往伴随较长的 Stop The World，应尽量避免频繁发生。

**记忆版：** Minor 清新生代；Old 清老年代；Mixed 是 G1 混合回收；Full 最重。

## 5. 什么是空间分配担保？

**通俗理解：** 新生代回收前，JVM 会先看看老年代有没有地方接收“万一还活着”的对象。老年代兜得住，Minor GC 才更安心。

**专业回答：** 空间分配担保是 Minor GC 前的一种风险判断。新生代采用复制算法，GC 后存活对象可能需要晋升到老年代。如果老年代可用连续空间不足以容纳可能晋升的对象，JVM 可能直接触发 Full GC，以获得更多空间。它的本质是为新生代存活对象向老年代晋升提供空间保障。

**记忆版：** Minor GC 前先问老年代：“我这批活对象你接得住吗？”

## 6. 如何判断一个对象是否应该被回收？

**通俗理解：** 判断对象是不是垃圾，本质看它还能不能被程序找到。找不到了，就可以回收。

**专业回答：** 常见判断方式有引用计数法和可达性分析法。引用计数法给对象维护引用数量，引用数为 0 则可回收，但无法解决循环引用问题。HotSpot 主要使用可达性分析法：从 GC Roots 出发向下搜索引用链，如果对象不可达，则说明对象不再存活，可以被回收。

**示例：循环引用不等于一定不能回收。**

```java
class Node {
    Node next;
}

Node a = new Node();
Node b = new Node();
a.next = b;
b.next = a;
a = null;
b = null;
// a、b 相互引用，但从 GC Roots 不可达，仍然可以被回收。
```

**记忆版：** HotSpot 看“从根能不能找到”；找不到就是不可达。

## 7. 什么是 GC Roots？

**通俗理解：** GC Roots 就是 JVM 判断对象存活时的“起点”。从这些起点一路能找到的对象，就暂时认为还活着。

**专业回答：** GC Roots 是可达性分析的根节点集合。常见 GC Roots 包括：虚拟机栈中局部变量表引用的对象、方法区中类静态属性引用的对象、方法区中常量引用的对象、本地方法栈中 JNI 引用的对象、被同步锁持有的对象、JVM 内部引用对象、活动线程相关对象等。

**记忆版：** GC Roots 常记：栈变量、静态变量、常量、JNI、锁、活动线程。

## 8. 对象不可达后会立刻被回收吗？

**通俗理解：** 不一定。对象第一次被判定不可达后，还可能有一次“自救机会”，但这个机制现在很少建议使用。

**专业回答：** 对象在可达性分析中不可达后，并不一定立刻死亡。若对象重写了 `finalize()` 且该方法尚未执行过，JVM 可能将其放入队列，稍后执行 `finalize()`。对象如果在 `finalize()` 中重新与 GC Roots 建立引用，理论上可以逃过一次回收。但 `finalize()` 执行时机不确定、成本高且不可靠，已不推荐使用。

**记忆版：** 不可达不一定马上死；`finalize()` 可自救一次，但别依赖。

## 9. Java 的四种引用类型是什么？

**通俗理解：** 引用强弱决定对象“有多容易被 GC 回收”。强引用最硬，虚引用最弱，软引用和弱引用介于中间。

**专业回答：** Java 引用类型包括强引用、软引用、弱引用和虚引用。强引用是普通对象引用，只要强引用存在，对象就不会被回收。软引用适合缓存，内存不足时会被回收。弱引用强度更低，只要发生 GC，无论内存是否充足，弱引用对象通常都会被回收。虚引用不能通过引用获取对象，主要用于跟踪对象被回收的状态，通常配合引用队列使用。

**示例：**

```java
Object strong = new Object();
SoftReference<Object> soft = new SoftReference<>(new Object());
WeakReference<Object> weak = new WeakReference<>(new Object());
PhantomReference<Object> phantom = new PhantomReference<>(new Object(), new ReferenceQueue<>());
```

**记忆版：** 强引用不回收；软引用内存紧张回收；弱引用一 GC 就回收；虚引用只跟踪回收。

## 10. 如何判断常量是否是废弃常量？

**通俗理解：** 常量池里的常量如果已经没人用了，就像一本没人借的旧书，可以被清理。

**专业回答：** 运行时常量池中的常量如果没有任何对象引用它，就可以被判定为废弃常量。比如某个字符串常量已经没有任何 String 对象引用，在发生垃圾回收且条件满足时，就可能被回收。常量回收属于方法区/元空间相关回收的一部分。

**记忆版：** 常量没人引用，就是废弃常量。

## 11. 如何判断一个类是无用类？

**通俗理解：** 一个类如果实例没了、类加载器也没了、Class 对象也没人引用，就可能被卸载。

**专业回答：** 判断类是否无用通常需要同时满足三个条件：该类所有实例都已被回收；加载该类的 ClassLoader 已被回收；该类对应的 `java.lang.Class` 对象没有被引用，无法再通过反射访问。满足这些条件后，虚拟机可以卸载该类，但不是必然立即卸载。

**记忆版：** 无用类三没：没实例、没类加载器、没 Class 引用。

## 12. 常见垃圾回收算法有哪些？

**通俗理解：** 回收垃圾有几种思路：直接标出来清掉、把活对象搬到新地方、清完后把活对象往一边挪。

**专业回答：** 常见 GC 算法包括标记-清除、复制、标记-整理和分代收集。标记-清除先标记可回收对象再清除，简单但容易产生碎片。复制算法把存活对象复制到另一块空间，适合存活率低的新生代，但会浪费一部分空间。标记-整理先标记存活对象，再把存活对象向一端移动，适合老年代，能减少碎片。分代收集根据对象生命周期差异，在新生代和老年代使用不同算法。

**记忆版：** 标清会碎片；复制适合年轻代；标整适合老年代；分代是按年龄选算法。

## 13. 为什么新生代常用复制算法？

**通俗理解：** 新生代对象大多“朝生夕死”，真正活下来的很少。与其清很多垃圾，不如把少量活对象复制走，剩下整块清空。

**专业回答：** 新生代对象存活率低，复制算法只需要复制少量存活对象，效率较高。HotSpot 新生代通常划分为 Eden 和两个 Survivor 区，每次使用 Eden 和一个 Survivor，GC 后把存活对象复制到另一个 Survivor，然后清空原区域。这样可以减少碎片，并提高新生代回收效率。

**记忆版：** 新生代死得多、活得少，所以复制活对象最划算。

## 14. 为什么老年代通常不用复制算法？

**通俗理解：** 老年代对象活得久，存活比例高。如果用复制算法，要搬很多对象，还要准备很大一块空闲区域，成本太高。

**专业回答：** 老年代对象存活率较高，复制算法会产生大量对象复制成本，并需要额外预留较大空间作为复制目标，不适合老年代。因此老年代更常使用标记-清除或标记-整理算法。标记-整理能减少内存碎片，更适合长期运行的老年代回收场景。

**记忆版：** 老年代活得多，复制太贵；常用标记-清除/整理。

## 15. 什么是 Stop The World？

**通俗理解：** STW 就是 GC 工作时，用户线程需要暂停一下，让 JVM 专心判断和整理对象。暂停越久，用户越可能感觉卡顿。

**专业回答：** Stop The World 指垃圾回收过程中 JVM 暂停所有用户线程，只保留 GC 线程执行的现象。STW 的目的是保证对象引用关系在分析和移动过程中保持一致。不同垃圾收集器会尽量缩短 STW 时间，例如通过并发标记、并发整理、分区回收等方式降低停顿。

**记忆版：** STW = GC 暂停业务线程；面试关注“停顿时间”。

## 16. 并行和并发在 GC 中有什么区别？

**通俗理解：** 并行是多个 GC 线程一起干活；并发是 GC 线程和用户线程一起运行。

**专业回答：** 并行（Parallel）指多条 GC 线程同时执行垃圾回收工作，此时用户线程通常处于暂停状态。并发（Concurrent）指 GC 线程与用户线程同时运行，用户线程不必全程暂停，但并发阶段会带来额外协调成本，也可能产生浮动垃圾。

**记忆版：** 并行 = GC 多线程；并发 = GC 和业务一起跑。

## 17. 常见垃圾收集器有哪些？

**通俗理解：** 垃圾收集器就是 GC 算法的具体实现。不同收集器侧重点不同：有的简单，有的追求吞吐量，有的追求低停顿。

**专业回答：** HotSpot 常见垃圾收集器包括 Serial、ParNew、Parallel Scavenge、Serial Old、Parallel Old、CMS、G1、ZGC 等。Serial 系列简单但会单线程 STW；Parallel 系列关注吞吐量；CMS 关注低停顿，但存在内存碎片和浮动垃圾问题；G1 面向服务端应用，按 Region 管理堆，兼顾吞吐和可控停顿；ZGC 是低延迟收集器，目标是极低停顿。

**记忆版：** Serial 简单；Parallel 吞吐；CMS 低停顿但有碎片；G1 综合；ZGC 超低停顿。

## 18. Serial 收集器有什么特点？

**通俗理解：** Serial 是最基础的收集器，只有一个 GC 线程工作，回收时会暂停其他线程，适合简单小内存场景。

**专业回答：** Serial 是单线程新生代收集器，使用复制算法。执行 GC 时会 Stop The World，并由一条 GC 线程完成回收。Serial Old 是 Serial 的老年代版本，通常使用标记-整理算法。它们实现简单、额外线程开销小，适合客户端、小堆或单核环境。

**记忆版：** Serial = 单线程 GC + STW；简单但停顿明显。

## 19. ParNew 收集器有什么特点？

**通俗理解：** ParNew 可以理解成 Serial 的多线程版本，多个 GC 线程一起清理新生代。

**专业回答：** ParNew 是 Serial 新生代收集器的多线程版本，也使用复制算法。它曾经常与 CMS 老年代收集器搭配使用，因为 CMS 需要一个能配合它的新生代收集器。ParNew 在多核环境下比 Serial 更适合服务端应用，但仍然会发生 STW。

**记忆版：** ParNew = 多线程 Serial，常和 CMS 搭配。

## 20. Parallel Scavenge 收集器有什么特点？

**通俗理解：** Parallel Scavenge 更关心整体效率，也就是单位时间内程序真正干业务的比例。

**专业回答：** Parallel Scavenge 是新生代并行收集器，使用复制算法，目标是获得可控制的高吞吐量。吞吐量可以理解为用户代码运行时间占总运行时间的比例。Parallel Old 是它的老年代版本，使用标记-整理算法。它们常用于后台计算、批处理等更关注吞吐量而不是极低停顿的场景。

**记忆版：** Parallel 系列关键词：并行、高吞吐、后台任务友好。

## 21. CMS 收集器有什么特点？

**通俗理解：** CMS 想让 GC 和业务线程尽量同时工作，从而减少停顿。但它清理后可能留下碎片，也可能在清理过程中又产生新垃圾。

**专业回答：** CMS（Concurrent Mark Sweep）是一款以获取最短回收停顿时间为目标的老年代收集器，主要使用标记-清除算法。流程一般包括初始标记、并发标记、重新标记、并发清除。初始标记和重新标记需要 STW，并发标记和并发清除可以和用户线程同时执行。CMS 的缺点包括对 CPU 资源敏感、无法处理浮动垃圾、基于标记-清除会产生内存碎片。

**记忆版：** CMS = 并发标记清除；低停顿，但有碎片和浮动垃圾。

## 22. G1 收集器有什么特点？

**通俗理解：** G1 不再简单按一整块新生代、老年代来回收，而是把堆切成很多小块 Region，优先回收收益最高的区域。

**专业回答：** G1（Garbage First）是面向服务端应用的垃圾收集器。它把堆划分为多个大小相等的 Region，每个 Region 可以扮演 Eden、Survivor 或 Old 的角色。G1 通过记录每个 Region 的垃圾回收价值，在允许的停顿时间内优先回收价值最高的 Region。它整体采用标记-整理思想，局部 Region 之间采用复制算法，能减少内存碎片，并支持可预测停顿。

**记忆版：** G1 = Region 分区 + 优先回收垃圾多的区 + 可控停顿。

## 23. ZGC 收集器有什么特点？

**通俗理解：** ZGC 追求极低停顿，适合大内存、低延迟系统。它尽量让大部分 GC 工作和业务线程一起做。

**专业回答：** ZGC 是一款可扩展低延迟垃圾收集器，目标是在大堆内存下仍保持很短的停顿时间。它通过并发标记、并发转移、读屏障、染色指针等技术，把大部分回收工作与用户线程并发执行。ZGC 更适合对延迟敏感、堆内存较大的服务端应用。

**记忆版：** ZGC = 大堆低延迟，核心目标是极短 STW。

## 24. 什么是浮动垃圾？

**通俗理解：** GC 并发清理时，业务线程还在运行，这期间新产生的垃圾，当前这一轮可能来不及清掉，只能留到下一轮。

**专业回答：** 浮动垃圾指并发垃圾回收过程中，由于用户线程仍在执行，对象引用关系持续变化而产生的新垃圾。这些垃圾在当前 GC 标记阶段之后才出现，因此通常无法在本轮回收中被处理，需要等下一次 GC。CMS、G1、ZGC 等带并发阶段的收集器都需要处理类似问题。

**记忆版：** 浮动垃圾 = 并发 GC 期间新产生、本轮来不及收的垃圾。

## 25. 为什么频繁 Full GC 是危险信号？

**通俗理解：** Full GC 像一次大扫除，暂停时间长。如果经常发生，说明内存压力很大，应用可能卡顿甚至 OOM。

**专业回答：** Full GC 回收范围大，通常伴随较长 STW，会影响应用响应时间和吞吐量。频繁 Full GC 可能由老年代空间不足、元空间不足、大对象过多、内存泄漏、晋升失败、System.gc() 调用、堆参数不合理等原因引起。排查时通常结合 GC 日志、堆转储、对象分布、线程栈和监控指标分析。

**记忆版：** Full GC 频繁 = 内存压力或参数/代码问题；要看日志和堆对象。

## 26. JVM GC 面试怎么完整回答？

**通俗理解：** 面试不要只背“GC 是垃圾回收”，要按一条线讲：对象在哪、怎么判断死活、怎么回收、谁来回收、怎么优化。

**专业回答：** 可以按五层回答：第一，GC 主要回收堆中的无用对象；第二，对象大多在新生代 Eden 分配，活久后晋升老年代；第三，HotSpot 通过可达性分析和 GC Roots 判断对象是否存活；第四，常见算法有标记-清除、复制、标记-整理和分代收集；第五，不同收集器侧重点不同，例如 Parallel 关注吞吐，CMS/G1/ZGC 更关注停顿控制。最后补充频繁 Full GC 需要结合日志和堆分析定位。

**记忆版：** 回答 GC 五步：内存区域 -> 对象分配 -> 存活判断 -> 回收算法 -> 收集器与调优。

| Full GC | 全堆级别回收，停顿重，频繁出现要排查 |
| 可达性分析 | 从 GC Roots 出发，找不到就是不可达 |
| GC Roots | 栈变量、静态变量、常量、JNI、锁、活动线程 |
| 强引用 | 只要强引用存在，对象不回收 |
| 软引用 | 内存不足时回收，适合缓存 |
| 弱引用 | 一次 GC 后通常回收 |
| 虚引用 | 跟踪对象回收，不能直接取对象 |
| 标记-清除 | 简单，但会产生碎片 |
| 复制算法 | 适合新生代，复制少量存活对象 |
| 标记-整理 | 适合老年代，减少碎片 |
| Serial | 单线程，简单，小堆适用 |
| Parallel | 关注吞吐量 |
| CMS | 低停顿，但有碎片和浮动垃圾 |
| G1 | Region 分区，可控停顿 |
| ZGC | 大堆低延迟，极短 STW |
