## 一、Java 基础核心面试题

### 1. 面向对象

## 1. 谈谈你对面向对象的理解？面向对象的四大特性是什么？

**核心回答：** 面向对象是一种编程思想，它把现实世界中的事物抽象成程序中的对象，通过对象之间的协作完成业务逻辑。面向对象的四大特性是封装、继承、多态、抽象。

**详细解析：**

- 封装：把对象属性私有化，通过公开方法访问和修改，隐藏内部实现细节，提高安全性和复用性。
- 继承：子类复用父类属性和方法，并可扩展自己的功能。Java 类只支持单继承，但支持多接口实现。
- 多态：同一行为在不同对象上有不同表现，包括编译时多态和运行时多态。编译时多态常见于方法重载，运行时多态常见于方法重写。
- 抽象：抽取事物的核心特征和行为，忽略次要细节，常通过抽象类和接口实现，用于约束子类行为、统一代码规范。

**记忆版：** 面向对象四大特性：封装藏细节，继承做复用，多态看表现，抽象定规范。

## 2. 重载和重写的区别？

**核心回答：** 重载发生在同一个类中，方法名相同但参数列表不同；重写发生在父子类之间，子类重新实现父类方法。

| 对比维度 | 重载 Overload | 重写 Override |
| --- | --- | --- |
| 定义位置 | 同一个类中 | 子类与父类之间 |
| 方法签名 | 方法名相同，参数个数、类型或顺序不同 | 方法名、参数列表一致，返回值兼容 |
| 权限修饰符 | 无特殊限制 | 子类权限不能比父类更小 |
| 异常 | 无特殊限制 | 不能抛出比父类更宽的受检异常 |
| 执行时机 | 编译时多态 | 运行时多态 |

**记忆版：** 重载看参数，重写看父子。

## 3. 抽象类和接口的区别？

**核心回答：** 抽象类更像“模板”，强调代码复用；接口更像“规范”，强调能力约束。

**详细解析：**

- 继承方式：抽象类只能单继承；接口可以多实现，接口之间可以多继承。
- 成员变量：抽象类可以有普通变量和常量；接口中的变量默认是 `public static final` 常量。
- 成员方法：抽象类可以有普通方法、抽象方法、构造方法；接口在 JDK 8 后支持默认方法和静态方法，JDK 9 后支持私有方法，但没有构造方法。
- 设计思想：抽象类用于抽取公共属性和行为，接口用于定义能力和规范。

**记忆版：** 抽象类管“是什么”，接口管“能做什么”。

### 2. Java 异常

## 4. Java 异常体系结构？Error、Exception、RuntimeException 的区别？

**核心回答：** Java 异常体系顶层是 `Throwable`，下面分为 `Error` 和 `Exception`。`Exception` 又分为受检异常和运行时异常。

**详细解析：**

- `Error`：JVM 级严重错误，通常程序无法处理，例如 `OutOfMemoryError`、`StackOverflowError`。
- `Exception`：程序可以捕获并处理的异常。
- 受检异常：除 `RuntimeException` 及其子类外的 `Exception`，编译期必须处理，例如 `IOException`、`SQLException`。
- 运行时异常：`RuntimeException` 及其子类，编译期不强制处理，例如 `NullPointerException`、`ArrayIndexOutOfBoundsException`、`ClassCastException`。

**记忆版：** `Throwable` 分两支：`Error` 是大事故，`Exception` 是可处理问题。

## 5. try-catch-finally 执行顺序？finally 一定会执行吗？

**核心回答：** 通常先执行 `try`，出现异常执行 `catch`，最后执行 `finally`。但 `finally` 不是绝对一定执行。

**详细解析：**

- 常规顺序：`try` -> `catch` -> `finally`。
- 如果 `try` 或 `catch` 中有 `return`，会先缓存返回值，再执行 `finally`，最后返回。
- `finally` 不执行的情况：执行 `System.exit(0)` 终止 JVM；JVM 崩溃、断电、线程被强制终止等。

**记忆版：** `return` 挡不住 `finally`，但 `System.exit()` 可以。

## 6. throw 和 throws 的区别？

**核心回答：** `throw` 用在方法体内，真正抛出一个异常对象；`throws` 用在方法声明上，声明方法可能抛出的异常类型。

**详细解析：**

- `throws`：写在方法声明上，告知调用方需要处理异常，可以声明多个异常。
- `throw`：写在方法体内部，主动抛出异常对象，一次只能抛出一个异常。

**记忆版：** `throw` 抛对象，`throws` 声明类型。

### 3. Java 集合

## 7. Java 集合的核心体系？Collection 和 Map 的区别？

**核心回答：** Java 集合分为 `Collection` 单列集合和 `Map` 双列集合。

**详细解析：**

- `Collection`：存储单个元素。
- `List`：有序、可重复，常见实现有 `ArrayList`、`LinkedList`、`Vector`。
- `Set`：无序、不可重复，常见实现有 `HashSet`、`LinkedHashSet`、`TreeSet`。
- `Map`：存储键值对，key 唯一，value 可重复，常见实现有 `HashMap`、`LinkedHashMap`、`TreeMap`、`Hashtable`。

**记忆版：** `Collection` 存单个元素，`Map` 存 key-value。

## 8. ArrayList 和 LinkedList 的区别？

**核心回答：** `ArrayList` 底层是动态数组，查询快；`LinkedList` 底层是双向链表，首尾增删更方便。

**详细解析：**

- 底层结构：`ArrayList` 基于动态数组；`LinkedList` 基于双向链表。
- 查询效率：`ArrayList` 支持随机访问，查询为 `O(1)`；`LinkedList` 需要遍历，查询为 `O(n)`。
- 增删效率：`ArrayList` 中间增删需要移动元素；`LinkedList` 修改节点指针即可。
- 内存占用：`ArrayList` 扩容可能浪费空间；`LinkedList` 每个节点要额外存前后指针。
- 线程安全：两者都不是线程安全集合。

**记忆版：** 查多用 `ArrayList`，首尾增删多用 `LinkedList`。

## 9. HashMap 底层原理？JDK 1.7 和 JDK 1.8 的区别？

**核心回答：** `HashMap` 通过哈希算法确定 key 的存储位置，并用链表或红黑树解决哈希冲突。

**详细解析：**

- JDK 1.7：数组 + 单向链表。
- JDK 1.8：数组 + 单向链表 + 红黑树。
- 树化条件：链表长度超过 8，且数组容量大于等于 64 时，链表转红黑树。
- 插入方式：JDK 1.7 使用头插法，多线程下可能产生环形链表；JDK 1.8 使用尾插法。
- 扩容机制：JDK 1.8 优化扩容，通过高位 0/1 拆分位置，减少重新计算。
- 空值：支持一个 `null` key 和多个 `null` value。

**记忆版：** 1.7 数组链表头插；1.8 数组链表红黑树尾插。

## 10. HashMap、Hashtable、ConcurrentHashMap 的区别？

**核心回答：** `HashMap` 非线程安全；`Hashtable` 线程安全但锁粒度粗；`ConcurrentHashMap` 线程安全且并发性能更好。

**详细解析：**

- `HashMap`：非线程安全，效率较高，允许 `null` key 和 `null` value。
- `Hashtable`：线程安全，方法整体加 `synchronized`，效率低，不允许 `null` key 和 `null` value，基本不推荐新项目使用。
- `ConcurrentHashMap`：线程安全，高并发场景首选。JDK 1.7 使用分段锁，JDK 1.8 使用 CAS + `synchronized`，锁粒度更细。

**记忆版：** `HashMap` 快但不安全，`Hashtable` 安全但慢，`ConcurrentHashMap` 安全且并发好。

### 4. Java 并发

## 11. 线程和进程的区别？

**核心回答：** 进程是资源分配的最小单位，线程是 CPU 调度的最小单位。

**详细解析：**

- 进程：独立占用内存和系统资源，进程之间相互独立，切换开销大。
- 线程：依附于进程存在，共享进程资源，切换开销小，也叫轻量级进程。
- 一个进程可以包含多个线程，多线程可以提高 CPU 利用率，实现并发执行。

**记忆版：** 进程管资源，线程管执行。

## 12. synchronized 和 Lock 的区别？

**核心回答：** `synchronized` 是 JVM 内置锁，自动加锁释放；`Lock` 是显式锁，需要手动加锁释放，但功能更灵活。

**详细解析：**

- 锁类型：`synchronized` 是内置锁；`Lock` 是代码层面的显式锁。
- 释放方式：`synchronized` 自动释放；`Lock` 必须在 `finally` 中手动 `unlock()`。
- 锁机制：`synchronized` 是可重入锁，通常非公平；`ReentrantLock` 支持公平和非公平。
- 功能扩展：`Lock` 支持超时锁、可中断锁、读写锁、多条件队列等。
- 性能：JDK 1.6 后 `synchronized` 经过偏向锁、轻量级锁等优化，常见场景性能已经不错。

**记忆版：** `synchronized` 简洁自动，`Lock` 手动灵活。

## 13. volatile 关键字的作用？能否保证线程安全？

**核心回答：** `volatile` 保证可见性和禁止指令重排，但不能保证复合操作的原子性。

**详细解析：**

- 可见性：一个线程修改 `volatile` 变量，其他线程能及时看到最新值。
- 有序性：禁止相关指令重排，常用于解决双重检查锁单例中的重排序问题。
- 不保证原子性：例如 `i++` 包含读取、加一、写回三个步骤，`volatile` 不能保证整体不可打断。

**记忆版：** `volatile` 管可见和有序，不管复合原子。

## 14. 线程池的核心参数？为什么不推荐使用 Executors 创建线程池？

**核心回答：** 线程池有七大核心参数，生产环境推荐使用 `ThreadPoolExecutor` 显式创建，避免 `Executors` 默认参数带来的 OOM 风险。

**详细解析：**

线程池核心参数：

- `corePoolSize`：核心线程数
- `maximumPoolSize`：最大线程数
- `keepAliveTime`：非核心线程空闲存活时间
- `unit`：时间单位
- `workQueue`：任务队列
- `threadFactory`：线程工厂
- `handler`：拒绝策略

不推荐 `Executors` 的原因：

- `FixedThreadPool`、`SingleThreadExecutor` 使用无界队列，高并发下任务堆积可能导致 OOM。
- `CachedThreadPool` 最大线程数接近无限，大量请求可能创建过多线程，耗尽系统资源。

**记忆版：** 线程池七参数；生产别偷懒用 `Executors`。

## 二、MySQL 数据库高频面试题

## 15. MySQL 事务四大特性 ACID 是什么？

**核心回答：** ACID 分别是原子性、一致性、隔离性、持久性。

**详细解析：**

- 原子性：事务是最小执行单元，要么全部成功，要么全部回滚。
- 一致性：事务执行前后，数据完整性和约束规则保持一致。
- 隔离性：多个事务并发执行时，相互隔离、互不干扰。
- 持久性：事务提交后，数据永久保存，宕机重启也不丢失。

**记忆版：** ACID：全成全败、状态正确、互不干扰、提交不丢。

## 16. MySQL 四大事务隔离级别？各自解决什么问题？

**核心回答：** 四大隔离级别从低到高是读未提交、读已提交、可重复读、串行化。InnoDB 默认是可重复读。

| 隔离级别 | 脏读 | 不可重复读 | 幻读 |
| --- | --- | --- | --- |
| 读未提交 | 可能 | 可能 | 可能 |
| 读已提交 | 不会 | 可能 | 可能 |
| 可重复读 | 不会 | 不会 | 可能，InnoDB 通过间隙锁/临键锁解决大部分场景 |
| 串行化 | 不会 | 不会 | 不会 |

**问题释义：**

- 脏读：读取到其他事务未提交的数据。
- 不可重复读：同一事务内多次读取同一行，结果不一致。
- 幻读：同一事务内多次范围查询，结果行数不一致。

**记忆版：** 隔离越高越安全，并发越低；MySQL 默认 RR。

## 17. InnoDB 和 MyISAM 的区别？

**核心回答：** InnoDB 支持事务、行锁、外键和崩溃恢复；MyISAM 不支持事务和外键，只支持表锁。

**详细解析：**

- 事务支持：InnoDB 支持事务；MyISAM 不支持。
- 锁机制：InnoDB 支持行锁和表锁；MyISAM 只支持表锁。
- 外键：InnoDB 支持；MyISAM 不支持。
- 崩溃恢复：InnoDB 有事务日志，宕机可恢复；MyISAM 崩溃后更容易损坏。
- 查询性能：MyISAM 在简单读多写少场景可能较快；InnoDB 综合能力更强，是主流选择。

**记忆版：** 业务默认 InnoDB；MyISAM 老、表锁、无事务。

## 18. MySQL 索引原理？B+ 树索引优势？

**核心回答：** InnoDB 常用 B+ 树索引，利用有序多路树结构减少磁盘 IO，并提升范围查询效率。

**详细解析：**

- 磁盘 IO 少：B+ 树节点能存更多索引项，树高更低，减少磁盘读写。
- 查询稳定：所有完整数据都在叶子节点，查询路径更稳定。
- 范围查询高效：叶子节点通过有序链表连接，适合范围查询、排序、分页。
- 非叶子节点只存索引，不存完整数据，占用空间小，单页能容纳更多索引。

**记忆版：** B+ 树优势：树矮、少 IO、范围强、查询稳。

## 19. 聚簇索引和非聚簇索引的区别？回表查询是什么？

**核心回答：** 聚簇索引叶子节点存整行数据；非聚簇索引叶子节点存索引列和主键值。通过二级索引再查主键索引拿整行数据的过程叫回表。

**详细解析：**

- 聚簇索引：通常是主键索引，叶子节点存储完整行数据，一张表只有一个。
- 非聚簇索引：也叫二级索引，叶子节点存储索引列和主键值。
- 回表查询：先通过二级索引查到主键，再通过主键索引查完整行数据。
- 覆盖索引：查询字段都在二级索引中，无需回表，是常见优化手段。

**记忆版：** 聚簇叶子放整行，二级索引叶子放主键；字段都在索引里就不回表。

## 20. 索引失效的常见场景？

**核心回答：** 索引失效通常是因为 SQL 写法让数据库无法按索引有序结构快速定位。

**常见场景：**

- 对索引列使用函数、运算或隐式类型转换。
- 模糊查询使用左模糊或全模糊，例如 `%xx`、`%xx%`。
- 使用 `or` 连接无索引字段。
- 使用 `not in`、`not exists`、`is not null` 等可能导致索引效果变差。
- 联合索引不遵循最左匹配原则。
- 优化器判断全表扫描成本更低，主动放弃索引。

**记忆版：** 函数运算、左模糊、乱用 OR、跳过最左列，都容易索引失效。

## 21. 慢查询优化的通用思路？

**核心回答：** 慢查询优化先定位 SQL，再看执行计划，最后从索引、SQL、表结构和架构层面优化。

**详细解析：**

- 定位慢 SQL：开启慢查询日志，找执行时间长、扫描行数多的 SQL。
- 分析执行计划：使用 `EXPLAIN` 查看索引使用、扫描行数、是否回表、是否临时表或文件排序。
- 索引优化：建立合适联合索引，使用覆盖索引，避免索引失效。
- SQL 优化：避免 `select *`，优化子查询和 join，减少无效排序分组。
- 架构优化：大表分库分表、读写分离、缓存兜底。

**记忆版：** 慢 SQL 优化五步：日志、执行计划、索引、SQL、架构。

## 22. 什么是死锁？如何避免和解决死锁？

**核心回答：** 死锁是多个事务互相持有对方需要的锁，并互相等待，导致无法继续执行。

**详细解析：**

死锁四个必要条件：

- 互斥条件
- 请求保持条件
- 不可剥夺条件
- 循环等待条件

避免和解决方案：

- 统一事务获取锁的顺序，避免循环等待。
- 缩短事务执行时间，尽早提交或回滚。
- 设置锁等待超时时间，开启死锁检测。
- 减少事务内锁数量，避免一次占用过多资源。

**记忆版：** 死锁是互相等锁；解决靠统一顺序、缩短事务、超时检测、少拿锁。
