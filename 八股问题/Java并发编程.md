## 1. 为什么要使用并发编程？

**通俗理解：** 并发编程就是让多个任务同时推进。比如一个任务等 IO 时，CPU 可以去做别的事，不用傻等。

**专业回答：** 使用并发编程可以充分利用多核 CPU 的计算能力，提高系统吞吐量；也可以把复杂业务拆分为多个并行任务，提升响应速度和并发处理能力。高并发系统、IO 密集型任务、异步任务处理都经常依赖并发编程。

**记忆版：** 并发的目的：榨干 CPU、提升吞吐、拆分业务。

## 2. 并发编程有什么缺点？

**通俗理解：** 并发能提速，但会让程序变复杂。多个线程一起改数据，稍不注意就会出现错乱。

**专业回答：** 并发编程可能带来线程安全问题、死锁、上下文切换开销、调试困难、内存泄漏、资源竞争等问题。如果任务很简单或线程过多，反而可能因为调度和切换成本导致性能下降。

**记忆版：** 并发不是免费午餐，问题集中在线程安全、死锁、切换开销。

## 3. 并发编程三要素是什么？

**通俗理解：** 多线程安全主要看三件事：操作是不是一次完成，别人能不能看见修改，执行顺序会不会乱。

**专业回答：** 并发编程三要素是原子性、可见性、有序性。原子性表示操作不可被中断；可见性表示一个线程修改共享变量后，其他线程能及时看到；有序性表示程序执行顺序符合预期，避免指令重排序破坏并发语义。

**记忆版：** 三要素：原子性、可见性、有序性。

## 4. Java 程序中如何保证多线程运行安全？

**通俗理解：** 要么用安全的工具类，要么加锁，要么用原子类，核心是保护共享数据。

**专业回答：** 可以使用 `synchronized`、`Lock`、`volatile`、`Atomic` 原子类、线程安全集合、不可变对象、`ThreadLocal` 等方式保证线程安全。原子性通常用锁或原子类，可见性可用 `volatile`、锁，有序性可通过 happens-before 规则和内存屏障保证。

**记忆版：** 原子性靠锁/Atomic，可见性靠 volatile/锁，有序性靠 happens-before。

## 5. 并发、并行、串行有什么区别？

**通俗理解：** 串行是一件一件做；并发是一个人切换着做多件事；并行是多个人真的同时做多件事。

**专业回答：** 串行是多个任务按顺序执行；并发是多个任务在同一时间段内交替推进，宏观上像同时执行；并行是多个任务在同一时刻真正同时执行，通常依赖多核 CPU。

**记忆版：** 串行按顺序，并发交替做，并行同时做。

## 6. 什么是多线程？多线程有哪些优缺点？

**通俗理解：** 多线程就是一个程序里有多条执行路线。好处是效率高，坏处是要处理资源竞争。

**专业回答：** 多线程是指一个进程内同时存在多个线程执行不同任务。优点是提高 CPU 利用率、提升响应速度、适合异步和并发任务。缺点是线程占用内存，线程切换有成本，共享资源访问需要同步，容易出现线程安全和死锁问题。

**记忆版：** 多线程优点是快，缺点是复杂。

## 7. 进程和线程有什么区别？

**通俗理解：** 进程像一个工厂，线程像工厂里的工人。工厂之间资源独立，工人共享同一个工厂的资源。

**专业回答：** 进程是操作系统资源分配的基本单位，拥有独立地址空间；线程是 CPU 调度和执行的基本单位，同一进程内线程共享进程资源，但每个线程有自己的栈和程序计数器。进程切换开销大，线程切换开销相对小。

**记忆版：** 进程管资源，线程管执行。

## 8. 什么是上下文切换？

**通俗理解：** CPU 从一个线程切到另一个线程前，要先保存当前线程进度，下次回来才能接着干。

**专业回答：** 上下文切换是 CPU 从一个任务切换到另一个任务时，保存当前任务状态并加载下一个任务状态的过程。它会消耗 CPU 时间，线程过多会增加上下文切换成本，导致性能下降。

**记忆版：** 上下文切换 = 保存现场 + 恢复现场。

## 9. 用户线程和守护线程有什么区别？

**通俗理解：** 用户线程是主角，守护线程是服务员。主角都结束了，服务员也跟着结束。

**专业回答：** 用户线程执行具体业务任务，守护线程在后台为用户线程服务，如 GC 线程。当所有用户线程结束时，JVM 会退出，不会等待守护线程完成。`setDaemon(true)` 必须在 `start()` 之前调用。

**记忆版：** 用户线程决定 JVM 活不活，守护线程不阻止 JVM 退出。

## 10. 什么是线程死锁？

**通俗理解：** 两个线程各拿着一把锁，又都等对方手里的锁，谁也不放，程序就卡住了。

**专业回答：** 死锁是两个或多个线程在执行过程中因争夺资源而互相等待，且没有外力干预时都无法继续执行的状态。典型场景是线程 A 持有锁 1 等锁 2，线程 B 持有锁 2 等锁 1。

**记忆版：** 死锁 = 互相拿锁 + 互相等待。

## 11. 形成死锁的四个必要条件是什么？

**通俗理解：** 死锁要成立，需要资源独占、拿着不放、不能抢、等待成环。

**专业回答：** 四个必要条件是互斥条件、请求与保持条件、不剥夺条件、循环等待条件。只要破坏其中任意一个条件，就可以避免死锁。

**记忆版：** 互斥、保持、不剥夺、循环等待。

## 12. 如何避免线程死锁？

**通俗理解：** 不要让线程拿锁顺序乱套；能一次拿齐资源就一次拿齐；拿不到锁就别一直死等。

**专业回答：** 可以通过固定加锁顺序破坏循环等待；一次性申请全部资源破坏请求与保持；使用 `tryLock` 设置超时时间，拿不到锁主动释放已有资源；减少锁粒度和同步代码范围；优先使用并发工具类。

**记忆版：** 防死锁：定顺序、少持有、可超时、小锁粒度。

## 13. 创建线程有哪几种方式？

**通俗理解：** 可以直接继承线程类，也可以把任务交给线程，还可以用有返回值的任务，实际开发更推荐线程池。

**专业回答：** 常见方式包括继承 `Thread`、实现 `Runnable`、实现 `Callable` 配合 `FutureTask`、使用线程池。实际开发不建议频繁手动创建线程，更推荐使用线程池统一管理线程生命周期。

**记忆版：** Thread、Runnable、Callable、线程池。

## 14. `start()` 和 `run()` 有什么区别？

**通俗理解：** `start()` 是启动新线程；直接调 `run()` 只是普通方法调用。

**专业回答：** 调用 `start()` 会让线程进入就绪状态，等待 CPU 调度后由 JVM 调用 `run()` 执行线程任务。直接调用 `run()` 不会创建新线程，而是在当前线程中同步执行普通方法。

**记忆版：** `start()` 开新线程，`run()` 普通调用。

## 15. Callable、Future、FutureTask 分别是什么？

**通俗理解：** `Callable` 负责干活并返回结果，`Future` 负责拿结果，`FutureTask` 可以把任务包装成可执行、可获取结果的对象。

**专业回答：** `Callable` 类似 `Runnable`，但可以返回结果并抛出异常。`Future` 表示异步任务结果，可以判断任务状态、取消任务、获取结果。`FutureTask` 同时实现 `Runnable` 和 `Future`，可以包装 `Callable` 或 `Runnable`，既能被线程执行，也能获取执行结果。

**记忆版：** Callable 产结果，Future 拿结果，FutureTask 包任务。

## 16. 线程生命周期有哪些状态？

**通俗理解：** 线程从新建、能运行、正在运行，到等待/阻塞，最后结束。

**专业回答：** Java 线程状态包括 `NEW`、`RUNNABLE`、`BLOCKED`、`WAITING`、`TIMED_WAITING`、`TERMINATED`。传统说法也会分为新建、就绪、运行、阻塞、死亡。线程状态会因 `start()`、获取锁失败、`wait()`、`sleep()`、`join()`、执行结束等行为发生转换。

**记忆版：** 新建、可运行、阻塞、等待、超时等待、终止。

## 17. Java 线程调度算法是什么？

**通俗理解：** Java 线程最终由操作系统调度，优先级只是建议，不保证一定按优先级执行。

**专业回答：** Java 通常采用抢占式线程调度模型，优先让高优先级线程获得 CPU，但具体行为依赖 JVM 和操作系统实现。程序不应该强依赖线程优先级保证执行顺序。

**记忆版：** Java 抢占式调度，优先级不可靠。

## 18. `sleep()` 和 `wait()` 有什么区别？

**通俗理解：** `sleep()` 是线程自己睡一会儿，不放锁；`wait()` 是线程进入等待并释放锁，等别人通知。

**专业回答：** `sleep()` 是 `Thread` 的静态方法，不释放锁，时间到后自动恢复可运行状态。`wait()` 是 `Object` 的方法，必须在同步块或同步方法中调用，会释放对象锁，需要其他线程调用 `notify()` 或 `notifyAll()` 唤醒，也可以设置超时时间。

**记忆版：** `sleep` 不放锁，`wait` 放锁；`sleep` 属于 Thread，`wait` 属于 Object。

## 19. 为什么 `wait()` 要在循环中调用？

**通俗理解：** 线程被唤醒不代表条件一定满足，所以醒来后要再检查一次。

**专业回答：** `wait()` 可能发生虚假唤醒，也可能被唤醒后竞争到锁时条件已经被其他线程改变。因此应使用 `while` 循环检查条件，而不是用 `if` 只判断一次。

**记忆版：** `wait` 标准写法：while 判断条件。

## 20. 为什么 `wait()`、`notify()`、`notifyAll()` 定义在 Object 类？

**通俗理解：** Java 里任何对象都可以当锁，所以等待和唤醒也应该属于对象。

**专业回答：** `wait/notify/notifyAll` 操作的是对象监视器，每个 Java 对象都可以作为锁对象。线程等待的是某个对象锁上的条件，因此这些方法定义在 `Object` 中，而不是 `Thread` 中。

**记忆版：** 锁属于对象，所以等待唤醒也属于对象。

## 21. 为什么 `wait()`、`notify()` 必须在同步代码块中调用？

**通俗理解：** 你要等待或通知某把锁，必须先拿到这把锁，否则 JVM 不知道你在操作哪个临界区。

**专业回答：** 调用 `wait()` 会释放当前对象锁并进入等待队列，调用 `notify()` 会唤醒等待该对象锁的线程。这些操作要求当前线程已经持有该对象监视器，否则会抛出 `IllegalMonitorStateException`。

**记忆版：** 先拿锁，才能 wait/notify。

## 22. `notify()` 和 `notifyAll()` 有什么区别？

**通俗理解：** `notify()` 随机叫醒一个等待线程，`notifyAll()` 把所有等待线程都叫醒，让它们重新抢锁。

**专业回答：** `notify()` 唤醒等待池中的一个线程，具体哪个由 JVM 决定。`notifyAll()` 唤醒等待池中的所有线程，它们会进入锁池竞争锁，竞争成功者继续执行。

**记忆版：** notify 一个，notifyAll 全部。

## 23. `yield()` 有什么作用？和 `sleep()` 有什么区别？

**通俗理解：** `yield()` 是“我先让一下 CPU，但我马上还能继续抢”；`sleep()` 是“我睡一会儿，到点再说”。

**专业回答：** `yield()` 让当前线程从运行状态回到就绪状态，具体是否让出 CPU 取决于调度器。`sleep()` 让当前线程进入阻塞或计时等待状态，时间到后恢复可运行。`sleep()` 会抛出 `InterruptedException`，`yield()` 不抛受检异常。

**记忆版：** `yield` 让步不保证，`sleep` 睡眠有时间。

## 24. 如何停止一个正在运行的线程？

**通俗理解：** 不建议强行杀线程，最好给它一个停止信号，让它自己安全退出。

**专业回答：** 推荐使用退出标志位或 `interrupt()` 协作式中断来停止线程。`stop()`、`suspend()`、`resume()` 已经过时，不推荐使用，因为可能破坏对象一致性或导致死锁。

**记忆版：** 停线程用标志位或 interrupt，不用 stop。

## 25. `interrupted()` 和 `isInterrupted()` 有什么区别？

**通俗理解：** 一个会看完后把中断标志清掉，一个只看不清。

**专业回答：** `Thread.interrupted()` 是静态方法，检查当前线程中断状态，并清除中断标志。`isInterrupted()` 是实例方法，用于检查目标线程是否被中断，不会清除中断标志。

**记忆版：** `interrupted` 会清标志，`isInterrupted` 不清。

## 26. Java 如何实现线程间通信和协作？

**通俗理解：** 线程之间可以通过共享变量、等待通知、阻塞队列等方式配合工作。

**专业回答：** 常见方式包括 `wait/notify/notifyAll`、`Condition.await/signal/signalAll`、共享变量、`volatile`、`BlockingQueue`、管道流、`CountDownLatch`、`CyclicBarrier` 等。生产者消费者模型通常推荐使用阻塞队列实现。

**记忆版：** 通信协作用 wait/notify、Condition、BlockingQueue、并发工具类。

## 27. 同步方法和同步代码块哪个更好？

**通俗理解：** 同步代码块更精细，只锁真正需要保护的那几行代码。

**专业回答：** 同步代码块通常更推荐，因为可以缩小锁范围，指定锁对象，减少无关代码被串行化，提高并发性能，也有助于降低死锁风险。同步方法会锁住整个方法，粒度更粗。

**记忆版：** 同步范围越小越好。

## 28. 什么是线程安全？

**通俗理解：** 多个线程一起访问同一段代码或数据，结果仍然正确，就是线程安全。

**专业回答：** 线程安全是指对象或方法在多线程环境下被并发访问时，无论线程如何调度，都能保持数据一致性和程序正确性。实现方式包括加锁、无锁原子操作、不可变对象、线程封闭等。

**记忆版：** 多线程访问，结果还对，就是线程安全。

## 29. `synchronized` 的作用和使用方式是什么？

**通俗理解：** `synchronized` 就是 Java 自带锁，让同一时刻只有一个线程进入被保护的代码。

**专业回答：** `synchronized` 用于实现同步，保证原子性、可见性和有序性。它可以修饰实例方法、静态方法和代码块。实例方法锁当前对象，静态方法锁当前类的 `Class` 对象，代码块锁括号中的对象。

**记忆版：** 实例方法锁对象，静态方法锁类，代码块锁指定对象。

## 30. `synchronized` 底层原理是什么？

**通俗理解：** JVM 会在进入同步代码时尝试拿对象监视器锁，退出时释放锁。

**专业回答：** 同步代码块底层通过 `monitorenter` 和 `monitorexit` 字节码指令实现，进入时获取对象监视器，退出时释放。同步方法通过方法访问标志 `ACC_SYNCHRONIZED` 实现。JDK 6 以后对 `synchronized` 做了偏向锁、轻量级锁、自旋锁、锁消除、锁粗化等优化。

**记忆版：** 代码块靠 monitorenter/monitorexit，方法靠 ACC_SYNCHRONIZED。

## 31. `synchronized` 为什么是可重入锁？

**通俗理解：** 同一个线程已经拿到锁后，再进入同一把锁保护的代码，不会把自己卡死。

**专业回答：** 可重入锁会记录持锁线程和重入次数。线程第一次获取锁时计数加一，同一线程再次获取同一把锁时继续加一；每释放一次计数减一，直到计数为 0 才真正释放锁。

**记忆版：** 同线程可重复拿锁，靠计数器释放。

## 32. `synchronized` 锁升级原理是什么？

**通俗理解：** 没竞争时锁很轻，有竞争时才慢慢升级，避免一开始就用重量级锁。

**专业回答：** `synchronized` 锁状态会随着竞争程度从无锁、偏向锁、轻量级锁升级到重量级锁。偏向锁适合单线程重复进入；轻量级锁通过 CAS 和自旋减少阻塞；竞争激烈时升级为重量级锁，线程阻塞等待操作系统调度。

**记忆版：** 无锁 -> 偏向锁 -> 轻量级锁 -> 重量级锁。

## 33. `synchronized` 和 `Lock` 有什么区别？

**通俗理解：** `synchronized` 是自动锁，简单省心；`Lock` 是手动锁，更灵活但要自己释放。

**专业回答：** `synchronized` 是 Java 关键字，由 JVM 管理锁获取和释放，异常时自动释放。`Lock` 是接口，常见实现是 `ReentrantLock`，需要手动 `lock()` 和 `unlock()`，支持可中断锁、超时获取锁、尝试获取锁、公平锁、多条件队列等能力。

**记忆版：** synchronized 自动简单，Lock 手动灵活。

## 34. `synchronized` 和 `ReentrantLock` 有什么区别？

**通俗理解：** 两者都能重入，但 `ReentrantLock` 能做更多事情，比如公平锁、尝试加锁、中断等待。

**专业回答：** 两者都是可重入锁。`synchronized` 是 JVM 层面的关键字，使用简单；`ReentrantLock` 是 JUC 下的类，基于 AQS 实现，支持公平锁和非公平锁、`tryLock()`、`lockInterruptibly()`、多个 `Condition` 等更灵活的功能。

**记忆版：** 都可重入；ReentrantLock 更灵活，synchronized 更简单。

## 35. `volatile` 的作用是什么？

**通俗理解：** `volatile` 能让一个线程改了变量后，其他线程马上看到；还能防止相关指令乱序。

**专业回答：** `volatile` 保证变量的可见性和禁止指令重排序，但不能保证复合操作的原子性。它适合状态标志、单次读写、双重检查锁中的实例引用等场景。

**记忆版：** volatile 保证可见性和有序性，不保证原子性。

## 36. `volatile` 和 Atomic 变量有什么区别？

**通俗理解：** `volatile` 只能保证看得见，`Atomic` 能保证类似自增这种操作不会被打断。

**专业回答：** `volatile` 保证变量读写的可见性和有序性，但 `count++` 这类复合操作仍非原子。`AtomicInteger` 等原子类基于 CAS 和 `volatile` 实现无锁原子更新，能保证自增、自减、比较交换等操作的原子性。

**记忆版：** volatile 管可见，Atomic 管原子更新。

## 37. `synchronized` 和 `volatile` 有什么区别？

**通俗理解：** `volatile` 像公告栏，大家都能看到最新值；`synchronized` 像门锁，同一时间只让一个人进去改。

**专业回答：** `volatile` 只能修饰变量，保证可见性和禁止重排序，不会阻塞线程，不能保证复合操作原子性。`synchronized` 可以修饰方法和代码块，保证原子性、可见性和有序性，但可能阻塞线程。

**记忆版：** volatile 轻量但不保原子；synchronized 重一些但更完整。

## 38. 什么是不可变对象？对并发有什么帮助？

**通俗理解：** 不可变对象创建后就不能改，多线程一起读也不会出问题。

**专业回答：** 不可变对象是创建后状态不能再改变的对象，典型如 `String`、包装类。不可变对象天然线程安全，因为不存在并发修改问题；正确构造的 `final` 字段还具有安全发布语义，可以减少同步开销。

**记忆版：** 不可变对象不用锁，天然适合并发读。

## 39. 什么是 CAS？会产生什么问题？

**通俗理解：** CAS 就是“先比较再替换”：如果值还是我刚才看到的，就更新；如果被别人改了，就失败重试。

**专业回答：** CAS 是 Compare And Swap，包含内存值 V、预期值 A、新值 B。只有当 V 等于 A 时才把 V 更新为 B，否则更新失败。CAS 是乐观锁思想，常用于原子类。问题包括 ABA 问题、自旋时间长 CPU 开销大、只能方便保证单个变量的原子操作。

**记忆版：** CAS 三个坑：ABA、自旋耗 CPU、只能单变量。

## 40. 什么是 AQS？

**通俗理解：** AQS 是很多锁和同步工具的地基，帮我们管理状态和排队等待的线程。

**专业回答：** AQS 是 `AbstractQueuedSynchronizer`，是构建锁和同步器的框架。它用一个 `volatile int state` 表示同步状态，通过 CAS 修改状态，用 FIFO 的 CLH 队列管理获取资源失败的线程。`ReentrantLock`、`Semaphore`、`CountDownLatch`、`ReentrantReadWriteLock` 等都基于 AQS。

**记忆版：** AQS = state + CAS + CLH 队列。

## 41. 什么是 ReentrantReadWriteLock？

**通俗理解：** 读写锁允许多个线程同时读，但写的时候必须独占。

**专业回答：** `ReentrantReadWriteLock` 是读写锁实现。读锁是共享锁，多个读线程可以同时持有；写锁是独占锁。读读不互斥，读写、写读、写写互斥。适合读多写少场景，并支持公平/非公平、可重入和锁降级。

**记忆版：** 读读共享，读写互斥，写写互斥。

## 42. 什么是 ConcurrentHashMap？

**通俗理解：** 它是线程安全且性能较好的 Map，适合高并发场景。

**专业回答：** `ConcurrentHashMap` 是线程安全的哈希表实现。JDK 7 主要采用 Segment 分段锁；JDK 8 取消 Segment，使用 CAS + `synchronized` 锁住桶或链表/红黑树头节点，并通过更细粒度控制提高并发性能。

**记忆版：** JDK7 分段锁，JDK8 CAS + synchronized。

## 43. 同步集合和并发集合有什么区别？

**通俗理解：** 同步集合通常一锁锁整块，并发集合锁得更细，所以并发性能更好。

**专业回答：** 同步集合如 `Vector`、`Hashtable`、`Collections.synchronizedMap()` 通常通过 `synchronized` 对方法加锁，粒度较粗，容易串行化。并发集合如 `ConcurrentHashMap`、`CopyOnWriteArrayList` 使用分段锁、CAS、写时复制等策略，提高并发性能和可伸缩性。

**记忆版：** 同步集合粗锁，并发集合细粒度。

## 44. CopyOnWriteArrayList 适合什么场景？

**通俗理解：** 写的时候复制一份新数组，读的时候不用加锁，所以适合读很多、写很少的场景。

**专业回答：** `CopyOnWriteArrayList` 采用写时复制策略。写操作会复制底层数组并修改副本，再替换引用；读操作无需加锁，迭代时不会抛出 `ConcurrentModificationException`。缺点是写操作开销大、占内存、实时性较弱。

**记忆版：** 读多写少用 COW，写多别用。

## 45. ThreadLocal 是什么？为什么可能内存泄漏？

**通俗理解：** `ThreadLocal` 给每个线程一份自己的变量副本，互不干扰。但在线程池里用完不清理，旧值可能一直跟着线程活着。

**专业回答：** `ThreadLocal` 提供线程局部变量，每个线程通过自己的 `ThreadLocalMap` 保存变量值，实现线程隔离。`ThreadLocalMap` 的 key 是 `ThreadLocal` 弱引用，value 是强引用；如果 key 被 GC 回收而 value 未清理，就可能出现 key 为 null 的 Entry，在线程池长生命周期线程中导致内存泄漏。使用后应调用 `remove()`。

**记忆版：** ThreadLocal 线程隔离，用完必须 remove。

## 46. 什么是阻塞队列？如何实现生产者消费者模型？

**通俗理解：** 阻塞队列是线程之间传递任务的安全队列。队列满了生产者等，队列空了消费者等。

**专业回答：** `BlockingQueue` 是支持阻塞插入和阻塞获取的队列。队列满时，生产者插入会等待；队列空时，消费者获取会等待。常见实现有 `ArrayBlockingQueue`、`LinkedBlockingQueue`、`PriorityBlockingQueue`、`DelayQueue`、`SynchronousQueue`、`LinkedTransferQueue`、`LinkedBlockingDeque`。它天然适合生产者消费者模型。

**记忆版：** 队满生产等，队空消费等。

## 47. 什么是线程池？有哪些优点？

**通俗理解：** 线程池就是提前准备一批线程，需要任务时复用它们，不用每次新建和销毁线程。

**专业回答：** 线程池管理一组可复用工作线程，用于执行提交的任务。优点包括降低线程创建销毁开销、提高响应速度、控制最大并发数、统一管理和监控线程、支持定时任务和拒绝策略等。

**记忆版：** 线程池 = 复用线程、控制并发、统一管理。

## 48. 常见线程池有哪些？

**通俗理解：** 常见线程池有单线程、固定大小、可缓存、定时任务几种。

**专业回答：** `Executors` 提供 `newSingleThreadExecutor`、`newFixedThreadPool`、`newCachedThreadPool`、`newScheduledThreadPool` 等工厂方法。但实际开发不推荐直接使用 `Executors` 创建线程池，建议使用 `ThreadPoolExecutor` 明确指定参数，避免队列过大或线程数过多导致 OOM。

**记忆版：** 面试答种类，实践用 ThreadPoolExecutor。

## 49. ThreadPoolExecutor 核心参数有哪些？

**通俗理解：** 线程池要知道核心线程多少、最多多少、任务放哪、满了怎么办。

**专业回答：** 核心参数包括 `corePoolSize`、`maximumPoolSize`、`keepAliveTime`、`unit`、`workQueue`、`threadFactory`、`handler`。其中核心线程数、最大线程数、任务队列、拒绝策略是重点。

**记忆版：** 核心、最大、存活时间、队列、线程工厂、拒绝策略。

## 50. 线程池有哪些状态？

**通俗理解：** 线程池从正常接任务，到不接新任务，再到停止、整理、终止。

**专业回答：** `ThreadPoolExecutor` 状态包括 `RUNNING`、`SHUTDOWN`、`STOP`、`TIDYING`、`TERMINATED`。`RUNNING` 接收新任务并处理队列；`SHUTDOWN` 不接新任务但处理队列；`STOP` 不接新任务、不处理队列并中断执行中任务；`TIDYING` 表示任务清空准备终止；`TERMINATED` 表示终止完成。

**记忆版：** RUNNING -> SHUTDOWN/STOP -> TIDYING -> TERMINATED。

## 51. `submit()` 和 `execute()` 有什么区别？

**通俗理解：** `execute()` 只提交任务，不返回结果；`submit()` 会返回 `Future`，可以拿结果或异常。

**专业回答：** `execute()` 只能提交 `Runnable`，没有返回值。`submit()` 可以提交 `Runnable` 或 `Callable`，返回 `Future`，可以通过 `get()` 获取结果或感知异常。

**记忆版：** execute 无返回，submit 有 Future。

## 52. 线程池队列满了会发生什么？

**通俗理解：** 如果队列满了，线程池会先尝试扩容线程；再满就按拒绝策略处理。

**专业回答：** 当运行线程数小于核心线程数时，创建核心线程执行任务；达到核心线程数后，任务进入队列；队列满且线程数小于最大线程数时，创建非核心线程；如果线程数已达最大且队列仍满，就触发拒绝策略。常见拒绝策略有 `AbortPolicy`、`CallerRunsPolicy`、`DiscardPolicy`、`DiscardOldestPolicy`。

**记忆版：** 核心满进队列，队列满扩线程，再满走拒绝。

## 53. 什么是原子操作？Java 有哪些原子类？

**通俗理解：** 原子操作就是不能被打断的操作。比如安全地加一，不能让多个线程加乱。

**专业回答：** 原子操作是不可被中断的一个或一系列操作。Java 的 `java.util.concurrent.atomic` 包提供原子类，如 `AtomicInteger`、`AtomicLong`、`AtomicBoolean`、`AtomicReference`，以及原子数组、原子字段更新器、解决 ABA 的 `AtomicStampedReference` 等。

**记忆版：** 原子类靠 CAS，让自增这类操作线程安全。

## 54. Atomic 原理是什么？

**通俗理解：** Atomic 类不是靠传统加锁，而是不断尝试 CAS，成功就更新，失败就重试。

**专业回答：** Atomic 类通常基于 `volatile` + CAS + Unsafe/native 方法实现。`volatile` 保证变量可见性，CAS 保证更新的原子性。更新失败的线程会自旋重试，直到成功或满足退出条件。

**记忆版：** Atomic = volatile 可见 + CAS 原子。

## 55. CountDownLatch 和 CyclicBarrier 有什么区别？

**通俗理解：** `CountDownLatch` 是一个线程等多个线程完成；`CyclicBarrier` 是多个线程互相等，等齐了一起走。

**专业回答：** `CountDownLatch` 通常用于一个或多个线程等待其他线程执行完成，调用 `countDown()` 不会阻塞，计数归零后等待线程继续执行，不能复用。`CyclicBarrier` 用于一组线程互相等待，调用 `await()` 会阻塞，直到所有线程到达屏障后一起继续执行，可以复用，并可指定屏障动作。

**记忆版：** Latch 一等多，不复用；Barrier 多等多，可复用。

## 56. Semaphore 有什么作用？

**通俗理解：** `Semaphore` 像限流器，规定最多几个线程能同时进入某段代码。

**专业回答：** `Semaphore` 是信号量，用于限制同时访问某个资源的线程数量。它内部维护许可证数量，线程进入前获取许可证，退出后释放许可证。当许可证为 1 时，效果类似互斥锁；当许可证大于 1 时，允许多个线程并发访问。

**记忆版：** Semaphore 控制并发数量。

## 57. Exchanger 是什么？

**通俗理解：** `Exchanger` 是两个线程交换数据的碰头点，双方都到了才能交换。

**专业回答：** `Exchanger` 是用于两个线程之间交换数据的并发工具。一个线程调用 `exchange()` 后会等待另一个线程也调用该方法，两个线程到达同步点后交换各自数据并继续执行。

**记忆版：** Exchanger = 两个线程到点换数据。

## 58. 两种创建并启动线程的流程和区别；线程同步的几种方式及区别？

**通俗理解：** 创建线程常见有两种基础方式：继承 `Thread`，或者实现 `Runnable`。同步就是多个线程操作共享数据时，加规则防止数据被改乱。

**方式一：继承 `Thread`**

```java
class MyThread extends Thread {
    @Override
    public void run() {
        System.out.println("线程执行任务");
    }
}

new MyThread().start();
```

**流程：**

1. 定义类继承 `Thread`。
2. 重写 `run()` 方法。
3. 创建线程对象。
4. 调用 `start()` 启动线程。

**方式二：实现 `Runnable`**

```java
class MyTask implements Runnable {
    @Override
    public void run() {
        System.out.println("线程执行任务");
    }
}

new Thread(new MyTask()).start();
```

**流程：**

1. 定义类实现 `Runnable`。
2. 重写 `run()` 方法。
3. 把任务对象传给 `Thread`。
4. 调用 `start()` 启动线程。

**两种方式区别：**

| 方式 | 优点 | 缺点 |
| --- | --- | --- |
| 继承 `Thread` | 写法直观，线程和任务放在一起 | Java 单继承，继承了 `Thread` 后不能再继承其他类 |
| 实现 `Runnable` | 任务和线程分离，更灵活；还能继承其他类；多个线程可共享同一个任务对象 | 不能直接返回结果，异常处理能力弱于 `Callable` |

**线程同步方式：**

| 同步方式 | 简单格式 | 特点 |
| --- | --- | --- |
| `synchronized` 方法 | `public synchronized void test() {}` | 使用简单，自动释放锁，锁粒度通常较粗 |
| `synchronized` 代码块 | `synchronized (lock) {}` | 可指定锁对象，锁范围更小，推荐优先掌握 |
| `Lock` / `ReentrantLock` | `lock.lock(); try {} finally { lock.unlock(); }` | 手动加锁释放，支持可中断、超时、公平锁等高级能力 |
| `volatile` | `private volatile boolean flag;` | 保证可见性和禁止重排序，不保证复合操作原子性 |
| 原子类 | `AtomicInteger count = new AtomicInteger();` | 基于 CAS，适合简单原子更新 |
| 线程安全集合 | `ConcurrentHashMap`、`CopyOnWriteArrayList` | 用现成并发容器减少手写锁 |

**专业回答：** 继承 `Thread` 和实现 `Runnable` 本质上都是把任务逻辑放进 `run()`，真正启动线程必须调用 `start()`。实际开发更推荐 `Runnable`、`Callable` 或线程池，因为任务和线程生命周期解耦。线程同步可以通过内置锁、显式锁、`volatile`、原子类、并发集合等实现，应根据是否需要原子性、可见性、锁粒度、是否需要返回结果等选择。

**记忆版：** 创建线程：继承 `Thread` 或实现 `Runnable`，启动都靠 `start()`；同步方式：锁、`volatile`、原子类、并发容器。
