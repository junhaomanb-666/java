# 数据库面试详解

> 本文件合并了本批次中重复出现的数据库问题。每题按“通俗理解 + 专业回答 + 记忆版”整理，尽量避免死记硬背。

## 1. 什么是索引？

**通俗理解：** 索引就像书的目录。没有目录要一页一页翻，有目录就能先定位章节，再找到内容。

**专业回答：** 数据库索引是一种用于加速数据检索的数据结构。它保存了索引列的值和对应数据位置之间的映射，使数据库可以减少全表扫描，提高查询效率。MySQL InnoDB 中常见索引结构是 B+ 树。

**记忆版：** 索引 = 数据库的目录，用空间和维护成本换查询速度。

## 2. 索引的数据结构有哪些？

**通俗理解：** 索引可以用不同“目录结构”实现。MySQL 最常见的是 B+ 树，因为它适合磁盘查询和范围查询。

**专业回答：** 常见索引结构包括 B+ 树索引、Hash 索引、全文索引、空间索引等。InnoDB 主要使用 B+ 树索引；Memory 引擎支持 Hash 索引；全文索引用于文本检索。

**记忆版：** MySQL 面试默认重点答 B+ 树，补充 Hash、全文、空间。

## 3. B 树和 B+ 树有什么区别？

**通俗理解：** B 树的“树枝”和“叶子”都能放数据；B+ 树只有叶子节点放完整数据，非叶子节点主要负责导航，而且叶子节点之间用链表连起来。

**专业回答：**

- B 树的非叶子节点和叶子节点都可以存储数据。
- B+ 树只有叶子节点存储完整数据，非叶子节点只存储键值和指针。
- B+ 树叶子节点之间通过链表连接，更适合范围查询。
- B+ 树非叶子节点更小，单页能存更多索引项，树高更低，磁盘 IO 更少。

**记忆版：** B 树节点都存数据；B+ 树数据只在叶子，叶子还串起来。

## 4. 数据库为什么用 B+ 树，不用 B 树？

**通俗理解：** 数据库查询经常要查范围，比如查 10 到 100。B+ 树叶子节点连成链表，范围查询可以一路往后扫，很顺；B 树就没这么方便。

**专业回答：** B+ 树更适合数据库磁盘存储，因为非叶子节点不保存完整数据，可以容纳更多键值，降低树高，减少磁盘 IO。同时叶子节点有序链表天然适合范围查询、排序扫描和分页查询。B 树虽然也能查找，但范围查询和磁盘页利用率不如 B+ 树。

**记忆版：** B+ 树查单个稳定，查范围更强，磁盘 IO 更少。

## 5. 使用 B+ 树的好处是什么？

**通俗理解：** B+ 树能让数据库少读磁盘、范围查询方便、查询性能稳定。

**专业回答：**

- 树高低，减少磁盘 IO。
- 叶子节点有序并相连，范围查询效率高。
- 所有数据都在叶子节点，查询路径长度更稳定。
- 非叶子节点只存键和指针，单个磁盘页能存更多索引项。

**记忆版：** 低树高、少 IO、范围强、性能稳。

## 6. 为什么 MySQL 不主要使用 Hash 索引？

**通俗理解：** Hash 像按身份证号直接定位，等值查询很快；但如果要查范围、排序、前缀匹配，它就不擅长。

**专业回答：** Hash 索引适合等值查询，但不支持范围查询、排序、最左前缀匹配，也无法很好利用联合索引的部分列。同时 Hash 冲突也需要额外处理。因此 InnoDB 默认使用 B+ 树索引，而不是 Hash 索引。

**记忆版：** Hash 等值快，范围排序弱；B+ 树更通用。

## 7. 什么是聚簇索引和非聚簇索引？

**通俗理解：** 聚簇索引的叶子节点直接放整行数据；非聚簇索引的叶子节点一般只放主键值，需要再通过主键去找整行。

**专业回答：** InnoDB 中，聚簇索引通常就是主键索引，叶子节点保存完整行数据。非聚簇索引也叫二级索引，叶子节点保存索引列和对应主键值。如果查询需要的字段不在二级索引中，就需要通过主键再次查询聚簇索引，这个过程叫回表。

**记忆版：** 聚簇索引叶子放整行；非聚簇索引叶子放主键。

## 8. 非聚簇索引一定会回表吗？

**通俗理解：** 不一定。如果二级索引里已经有你要的数据，就不用回表。

**专业回答：** 非聚簇索引不一定回表。当查询字段都能从二级索引中获得时，称为覆盖索引，不需要回表。只有查询字段不完全在二级索引中时，才需要根据主键值回到聚簇索引查询完整记录。

**例子：**

```sql
-- index(name, age)
SELECT name, age FROM user WHERE name = 'Tom';
```

这个查询可能走覆盖索引，不需要回表。

**记忆版：** 查的列都在索引里，就是覆盖索引，不回表。

## 9. 什么是联合索引？

**通俗理解：** 联合索引就是把多个字段合在一起做一个目录，比如 `(name, age, city)`。

**专业回答：** 联合索引是基于多个列共同建立的索引，例如 `index(a, b, c)`。它先按 `a` 排序，`a` 相同再按 `b` 排序，`b` 相同再按 `c` 排序。因此字段顺序会直接影响索引是否能被充分利用。

**记忆版：** 联合索引是多列组合目录，顺序很重要。

## 10. 联合索引遵循什么原则？

**通俗理解：** 联合索引像电话簿先按姓排，再按名排。你知道姓，可以继续找名；但只知道名，就很难直接利用这个目录。

**专业回答：** 联合索引遵循最左前缀原则。对于索引 `(a, b, c)`，查询条件从最左列 `a` 开始连续匹配时，索引才能被充分利用。如果跳过 `a` 只查 `b` 或 `c`，通常无法有效使用该联合索引。

**记忆版：** 从最左边开始，不能跳列。

## 11. 什么是最左前缀原则和最左匹配原则？

**通俗理解：** 两个说法面试里经常混用，核心意思都是联合索引要从最左边字段开始用。

**专业回答：** 最左前缀原则指联合索引从最左列开始，按照索引定义顺序连续匹配。最左匹配原则强调查询优化器使用联合索引时，会尽量从最左字段开始匹配，遇到范围查询后，范围列后面的列通常不能继续用于精确定位。

**例子：** 有联合索引 `(a, b, c)`：

- `WHERE a = 1`：可用
- `WHERE a = 1 AND b = 2`：可用
- `WHERE a = 1 AND b = 2 AND c = 3`：可用
- `WHERE b = 2`：通常不能充分使用
- `WHERE a = 1 AND c = 3`：只能较好利用 `a`
- `WHERE a > 1 AND b = 2`：`a` 可用于范围，`b` 通常不能继续用于精确定位

**记忆版：** 联合索引三句话：从左开始、连续匹配、范围后减弱。

## 12. 使用索引一定能提高查询性能吗？

**通俗理解：** 不一定。索引是目录，目录太多会占空间，更新数据时还要维护目录；如果查出来的数据太多，走目录还不如直接翻全书。

**专业回答：** 索引可以提高查询效率，但不是一定有效。低选择性字段、返回大量数据、索引失效、频繁写入、过多索引等场景下，索引可能收益很低甚至降低整体性能。索引会占用磁盘空间，并增加 `INSERT`、`UPDATE`、`DELETE` 的维护成本。

**记忆版：** 索引加速读，拖慢写；建错了可能没用。

## 13. 怎么查看索引是否被使用？怎么优化查询性能？

**通俗理解：** 用 `EXPLAIN` 看 SQL 执行计划，就像看数据库准备怎么走路：是走索引，还是全表扫描。

**专业回答：** 可以使用 `EXPLAIN` 或 `EXPLAIN ANALYZE` 查看执行计划，重点关注 `type`、`possible_keys`、`key`、`rows`、`Extra` 等字段。优化方向包括建立合适索引、避免索引失效、减少返回列、避免 `select *`、优化 join 条件、控制分页深度、拆分复杂 SQL、分析慢查询日志。

**记忆版：** 先 `EXPLAIN`，看 `key` 有没有用索引，再看 `rows` 扫了多少行。

## 14. 索引有哪几种类型？

**通俗理解：** 索引可以按功能分，比如主键索引、唯一索引、普通索引、联合索引、全文索引。

**专业回答：** MySQL 常见索引类型包括主键索引、唯一索引、普通索引、联合索引、全文索引、空间索引。InnoDB 从存储方式看，还可以分为聚簇索引和二级索引。

**记忆版：** 功能上记：主键、唯一、普通、联合、全文；InnoDB 里记：聚簇、二级。

## 15. MySQL 主要使用的两种索引是什么？

**通俗理解：** 如果从 InnoDB 角度看，最重要的是主键聚簇索引和普通二级索引。

**专业回答：** InnoDB 中主要关注聚簇索引和非聚簇索引。聚簇索引通常是主键索引，叶子节点保存完整行数据；非聚簇索引也叫二级索引，叶子节点保存索引列和主键值。

**记忆版：** InnoDB 两类核心索引：聚簇索引、二级索引。

## 16. 什么是事务？

**通俗理解：** 事务就是把一组数据库操作打包，要么全部成功，要么全部失败。比如转账，扣钱和加钱必须一起成功。

**专业回答：** 事务是数据库中一组逻辑操作单元，用于保证数据一致性。事务中的操作要么全部提交，要么全部回滚。事务依赖 ACID 特性保证可靠性。

**记忆版：** 事务 = 一组操作，要么全做，要么全不做。

## 17. 事务的四大特性 ACID 是什么？

**通俗理解：** 转账时，钱不能扣一半，数据不能乱，别人不能看到中间状态，提交后不能丢。

**专业回答：**

- 原子性：事务内操作不可分割，要么全部成功，要么全部失败。
- 一致性：事务执行前后，数据必须从一个一致状态变为另一个一致状态。
- 隔离性：多个事务并发执行时，彼此之间要有隔离效果。
- 持久性：事务提交后，数据修改应永久保存。

**记忆版：** ACID = 全成全败、状态正确、互不干扰、提交不丢。

## 18. 什么是事务隔离级别？MySQL 默认事务隔离级别是什么？

**通俗理解：** 隔离级别就是多个事务同时操作数据库时，彼此能看到对方修改到什么程度。

**专业回答：** SQL 标准定义了四种隔离级别：读未提交、读已提交、可重复读、串行化。MySQL InnoDB 默认隔离级别是 `REPEATABLE READ`。隔离级别越高，并发安全性越好，但并发性能通常越低。

**四种级别：**

- `READ UNCOMMITTED`：可能脏读
- `READ COMMITTED`：解决脏读，可能不可重复读
- `REPEATABLE READ`：解决不可重复读，MySQL 默认
- `SERIALIZABLE`：串行化，隔离最强，并发最低

**记忆版：** MySQL 默认 RR，可重复读。

## 19. 什么是脏读、不可重复读、幻读？

**通俗理解：**

- 脏读：读到了别人还没提交的数据。
- 不可重复读：同一行数据前后读两次，结果不一样。
- 幻读：同一个范围前后查两次，多了或少了几行，像出现幻影。

**专业回答：**

- 脏读：事务读取到其他事务未提交的数据。
- 不可重复读：同一事务中多次读取同一行数据，结果不同，通常由其他事务提交的更新或删除导致。
- 幻读：同一事务中多次范围查询，结果集行数发生变化，通常由其他事务插入或删除导致。

**记忆版：** 脏读读未提交；不可重复读看同一行变了；幻读看范围多了少了。

## 20. 隔离级别和锁有什么关系？

**通俗理解：** 隔离级别越高，数据库越要用锁或 MVCC 管住并发，避免事务之间互相影响。

**专业回答：** 隔离级别规定事务之间可见性的强弱，锁和 MVCC 是实现隔离级别的重要手段。低隔离级别加锁少、并发高但一致性弱；高隔离级别加锁更多或限制更多，并发降低但一致性更强。InnoDB 在可重复读下通过 MVCC、行锁、间隙锁、临键锁等机制减少脏读、不可重复读和幻读问题。

**记忆版：** 隔离级别是规则，锁和 MVCC 是实现手段。

## 21. 什么是锁？锁的机制是什么？

**通俗理解：** 锁就是多人同时改同一份数据时，用来排队和保护数据的机制。

**专业回答：** 数据库锁用于控制并发访问，保证数据一致性。事务访问数据时，可以通过共享锁、排他锁等方式限制其他事务的读写行为。锁机制会影响并发性能，锁范围越大，冲突概率越高。

**记忆版：** 锁 = 并发访问时保护数据的一把门锁。

## 22. 按锁的粒度分，数据库锁有哪些？

**通俗理解：** 锁可以锁整张表，也可以只锁某一行。锁得越小，并发越好，但管理更复杂。

**专业回答：**

- 表级锁：锁住整张表，开销小，冲突大，并发低。
- 行级锁：锁住具体数据行，开销大，冲突小，并发高。
- 页级锁：锁住数据页，粒度介于表锁和行锁之间。

**记忆版：** 表锁范围大，行锁并发高，页锁居中。

## 23. 乐观锁和悲观锁的区别？

**通俗理解：** 悲观锁觉得别人一定会抢，所以先锁住；乐观锁觉得冲突不多，先不锁，提交时再检查。

**专业回答：** 悲观锁在操作数据前先加锁，例如 `select ... for update`，适合冲突频繁场景。乐观锁不提前加锁，通常通过版本号或时间戳在更新时校验数据是否被修改，适合读多写少、冲突较少场景。

**记忆版：** 悲观先锁，乐观后验。

## 24. 什么是死锁？

**通俗理解：** 两个事务互相拿着对方想要的资源，谁也不放，谁也走不下去。

**专业回答：** 死锁是指两个或多个事务在执行过程中互相等待对方持有的锁资源，导致所有事务都无法继续执行。数据库通常会检测死锁，并回滚其中一个事务打破僵局。

**记忆版：** 你等我，我等你，谁都不释放。

## 25. MySQL 两种常见存储引擎的区别？

**通俗理解：** InnoDB 更适合正常业务系统，因为支持事务和行锁；MyISAM 更老，功能少，主要偏读。

**专业回答：** InnoDB 支持事务、外键、行级锁、崩溃恢复，默认使用聚簇索引，是 MySQL 默认存储引擎。MyISAM 不支持事务和外键，只支持表级锁，索引和数据分开存储，崩溃恢复能力弱。

**记忆版：** InnoDB 有事务、行锁、外键；MyISAM 表锁、无事务。

## 26. MyISAM 索引和 InnoDB 索引有什么区别？

**通俗理解：** InnoDB 的主键索引叶子节点直接存整行数据；MyISAM 的索引叶子节点存的是数据文件地址。

**专业回答：** InnoDB 使用聚簇索引组织表数据，主键索引的叶子节点保存完整行记录，二级索引叶子节点保存主键值。MyISAM 的索引和数据分离，索引叶子节点保存数据记录的物理地址，因此主键索引和普通索引结构上差别不如 InnoDB 明显。

**记忆版：** InnoDB 索引连着数据；MyISAM 索引指向数据地址。

## 27. 数据库三大范式是什么？

**通俗理解：** 范式就是设计表时减少重复、避免数据混乱的规则。

**专业回答：**

- 第一范式：字段具有原子性，不能再拆分。
- 第二范式：在满足第一范式基础上，非主键字段必须完全依赖主键，不能只依赖联合主键的一部分。
- 第三范式：在满足第二范式基础上，非主键字段不能依赖其他非主键字段，避免传递依赖。

**记忆版：** 1NF 字段不可拆；2NF 完全依赖主键；3NF 不传递依赖。

## 28. SQL 语句分为哪几类？

**通俗理解：** SQL 有的用来查数据，有的用来改表结构，有的用来控制权限和事务。

**专业回答：**

- DQL：数据查询语言，例如 `SELECT`
- DML：数据操作语言，例如 `INSERT`、`UPDATE`、`DELETE`
- DDL：数据定义语言，例如 `CREATE`、`ALTER`、`DROP`
- DCL：数据控制语言，例如 `GRANT`、`REVOKE`
- TCL：事务控制语言，例如 `COMMIT`、`ROLLBACK`

**记忆版：** 查询 DQL，增删改 DML，建改删表 DDL，权限 DCL，事务 TCL。

## 29. 字段为什么建议定义为非空？

**通俗理解：** `NULL` 不是空字符串，也不是 0，它代表未知。未知值会让判断和索引统计更复杂。

**专业回答：** 字段定义为 `NOT NULL` 可以避免三值逻辑带来的判断复杂度，减少空值处理成本，使数据语义更明确，也有利于索引统计和查询优化。实际设计中，如果业务允许缺省值，通常使用合理默认值代替 `NULL`。

**记忆版：** 能非空就非空，语义清楚，查询少踩坑。

## 30. 什么是子查询？可以用在哪些语句后？

**通俗理解：** 子查询就是 SQL 里面再嵌套一个查询，先查出一批结果，再给外层 SQL 使用。

**专业回答：** 子查询是嵌套在另一个 SQL 语句中的查询，可以出现在 `SELECT`、`FROM`、`WHERE`、`HAVING` 等位置，也可以用于 `INSERT`、`UPDATE`、`DELETE` 中提供条件或数据来源。

**记忆版：** 子查询 = 查询里套查询，常见于 `SELECT/FROM/WHERE/HAVING`。

## 31. 六种关联查询是什么？

**通俗理解：** 表连接就是把多张表按条件拼起来查。

**专业回答：** 常见连接包括内连接、左外连接、右外连接、全外连接、自连接、交叉连接。MySQL 不直接支持标准 `FULL OUTER JOIN`，通常用 `LEFT JOIN` 和 `RIGHT JOIN` 配合 `UNION` 实现。

**记忆版：** 内、左、右、全、自、交叉。

## 32. MySQL 中 in 和 exists 的区别？

**通俗理解：** `in` 更像先拿到一批值，再看外层值在不在里面；`exists` 更像逐行判断子查询有没有结果。

**专业回答：** `IN` 判断某个值是否在子查询结果集中；`EXISTS` 判断子查询是否至少返回一行。一般小结果集适合 `IN`，外表大且子查询能利用索引时 `EXISTS` 可能更合适。实际性能需要结合执行计划判断。

**记忆版：** `IN` 比值，`EXISTS` 看有没有。

## 33. UNION 和 UNION ALL 的区别？

**通俗理解：** `UNION` 会去重，`UNION ALL` 不去重，所以 `UNION ALL` 通常更快。

**专业回答：** `UNION` 会合并多个查询结果并去重，需要额外排序或哈希去重成本。`UNION ALL` 直接合并结果，不去重，性能通常更好。如果业务允许重复，应优先使用 `UNION ALL`。

**记忆版：** 要去重用 `UNION`，不去重用 `UNION ALL`。

## 34. 什么是触发器？使用场景有哪些？

**通俗理解：** 触发器就是数据库里的自动反应机制。某张表插入、修改、删除数据时，自动执行一段逻辑。

**专业回答：** 触发器是与表相关联的数据库对象，在 `INSERT`、`UPDATE`、`DELETE` 操作发生前或发生后自动执行。常见场景包括审计日志、数据校验、自动维护冗余字段、同步变更记录等。

**记忆版：** 触发器 = 增删改时自动执行的数据库逻辑。

## 35. MySQL 中有哪些触发器？应用在哪三种操作上？

**通俗理解：** 触发器按时间分为操作前和操作后，按动作分为插入、修改、删除。

**专业回答：** MySQL 触发器按触发时机分为 `BEFORE` 和 `AFTER`，按触发事件分为 `INSERT`、`UPDATE`、`DELETE`，因此常见组合有 `BEFORE INSERT`、`AFTER INSERT`、`BEFORE UPDATE`、`AFTER UPDATE`、`BEFORE DELETE`、`AFTER DELETE`。

**记忆版：** 两个时间：前后；三个动作：增改删。

## 36. 视图的优点是什么？

**通俗理解：** 视图像给复杂查询起了一个名字，别人可以直接查这个名字，不用关心底层 SQL 多复杂。

**专业回答：** 视图可以简化复杂 SQL、隐藏底层表结构、控制用户访问字段、提高逻辑复用性和安全性。但视图不等于性能优化，复杂视图底层仍可能执行复杂查询。

**记忆版：** 视图优点：简化 SQL、隐藏细节、控制权限。

## 37. 为什么要设定一个主键？

**通俗理解：** 主键就是每行数据的身份证号，用来唯一识别一条记录。

**专业回答：** 主键用于唯一标识表中的每一行记录，保证实体完整性。InnoDB 中主键还决定聚簇索引组织方式，因此建议使用短、稳定、递增的主键，减少页分裂和二级索引存储成本。

**记忆版：** 主键 = 行记录身份证；InnoDB 里还影响数据存储。

## 38. 数据库结构优化有哪些方向？

**通俗理解：** 表设计要让数据少重复、字段类型合适、索引合理、冷热数据分开。

**专业回答：** 数据库结构优化包括合理拆表与合表、字段类型优化、范式与反范式平衡、主键设计、索引设计、冷热数据分离、冗余字段控制、分库分表、归档历史数据等。核心目标是在一致性、性能、维护成本之间取平衡。

**记忆版：** 表、字段、索引、主键、冷热、拆分一起看。

## 39. 为什么要使用数据库？

**通俗理解：** 数据库帮我们安全、稳定、方便地保存和查询数据，比直接写文件更适合业务系统。

**专业回答：** 数据库提供结构化存储、查询语言、事务、一致性控制、并发控制、权限管理、备份恢复、索引优化等能力，适合管理大量共享数据。

**记忆版：** 数据库解决存储、查询、事务、并发、安全。

## 40. 什么是 MySQL？

**通俗理解：** MySQL 是一个常用的关系型数据库，用 SQL 操作表中的数据。

**专业回答：** MySQL 是开源关系型数据库管理系统，使用 SQL 作为查询语言，支持多种存储引擎。常用于 Web 应用、业务系统、数据管理等场景，默认存储引擎通常是 InnoDB。

**记忆版：** MySQL = 开源关系型数据库，核心是表 + SQL + InnoDB。

## 41. 视图有哪些特点？

**通俗理解：** 视图看起来像表，但它本身通常不真正保存数据，而是保存了一条查询规则。

**专业回答：** 视图是基于 SQL 查询定义的虚拟表。它可以像普通表一样被查询，能够隐藏底层表结构、封装复杂查询、控制用户可见字段。视图中的数据通常来自基础表，基础表变化后，视图查询结果也会随之变化。部分简单视图可以更新，但复杂视图通常不可更新。

**记忆版：** 视图 = 虚拟表，不存或少存数据，封装查询，依赖基础表。

## 42. 视图的缺点是什么？

**通俗理解：** 视图虽然让查询看起来简单，但底层 SQL 可能一点也不简单。你查视图时，数据库还是要执行背后的查询。

**专业回答：** 视图的缺点包括：复杂视图可能导致性能问题；视图嵌套过多会增加 SQL 理解和维护成本；部分视图不可更新；视图隐藏了底层 SQL，容易让开发者误以为查询很轻量；如果基础表结构变化，视图也可能失效。

**记忆版：** 视图缺点：性能不一定好，嵌套难维护，复杂视图难更新。

## 43. InnoDB 引擎的行锁是怎么实现的？

**通俗理解：** InnoDB 的行锁不是直接锁“这一整行数据文件”，而是通过索引来锁定记录。能走索引时锁得细，不能走索引时可能锁很多行。

**专业回答：** InnoDB 行锁是基于索引实现的。执行更新、删除或 `select ... for update` 时，如果 SQL 命中索引，InnoDB 会锁住索引记录对应的数据行；如果没有使用索引，可能退化为扫描大量记录并加锁，表现上接近表锁。InnoDB 常见锁算法包括记录锁、间隙锁和临键锁，用于在不同隔离级别下保证并发一致性。

**记忆版：** InnoDB 行锁锁的是索引；不走索引，行锁可能变“大锁”。

## 44. 从锁的类别上分，数据库锁有哪些？

**通俗理解：** 如果按锁的作用来分，常见有共享锁、排他锁、乐观锁、悲观锁、意向锁等。

**专业回答：** 数据库锁按类别可以分为共享锁和排他锁。共享锁又叫读锁，多个事务可以同时读，但会限制写；排他锁又叫写锁，一个事务加写锁后，其他事务通常不能再加读锁或写锁。按并发控制思想还可以分为乐观锁和悲观锁。InnoDB 中还存在意向锁，用于协调表锁和行锁。

**记忆版：** 类别记：读锁、写锁；思想记：乐观、悲观；InnoDB 还有意向锁。

## 45. MySQL 中通常使用哪几种存储引擎？

**通俗理解：** 存储引擎就是表底层怎么存、怎么查、支不支持事务的实现方式。最常见的是 InnoDB 和 MyISAM。

**专业回答：** MySQL 常见存储引擎包括 InnoDB、MyISAM、Memory、Archive、CSV 等。业务开发中最常用的是 InnoDB 和 MyISAM，其中 InnoDB 是 MySQL 5.5 之后的默认存储引擎，也是当前主流选择。

**记忆版：** 常见引擎：InnoDB、MyISAM、Memory；默认主流是 InnoDB。

## 46. SQL 约束有哪些？

**通俗理解：** 约束就是给表里的数据定规矩，防止乱填，比如主键不能重复、字段不能为空。

**专业回答：** 常见 SQL 约束包括：主键约束 `PRIMARY KEY`、唯一约束 `UNIQUE`、非空约束 `NOT NULL`、默认值约束 `DEFAULT`、外键约束 `FOREIGN KEY`、检查约束 `CHECK`。它们用于保证数据完整性和业务规则。

**记忆版：** 约束记六个：主键、唯一、非空、默认、外键、检查。

## 47. 什么是 SQL？

**通俗理解：** SQL 是和关系型数据库沟通的语言，用它来查数据、改数据、建表、控制权限。

**专业回答：** SQL 是 Structured Query Language，结构化查询语言，用于操作关系型数据库。它包括数据查询、数据操作、数据定义、权限控制和事务控制等能力，例如 `SELECT`、`INSERT`、`UPDATE`、`DELETE`、`CREATE`、`ALTER`、`COMMIT` 等。

**记忆版：** SQL = 操作关系型数据库的标准语言。

## 48. 什么是存储过程？

**通俗理解：** 存储过程就是提前保存在数据库里的“一段 SQL 程序”，需要时直接调用。

**专业回答：** 存储过程是一组预先编译并保存在数据库中的 SQL 语句集合，可以接收参数、执行流程控制、完成复杂业务逻辑。调用存储过程时，数据库直接执行已定义好的逻辑。

**记忆版：** 存储过程 = 存在数据库里的 SQL 方法。

## 49. 存储过程的优缺点是什么？

**通俗理解：** 存储过程的好处是执行集中、复用方便；坏处是业务逻辑放进数据库后，代码不容易维护，也不容易迁移。

**专业回答：** 存储过程的优点包括减少网络传输、封装复杂 SQL、提高复用性、可以统一数据库侧逻辑。缺点包括可读性和调试体验较差，业务逻辑容易和数据库强绑定，迁移成本高，版本管理和团队协作不如应用代码方便。

**记忆版：** 优点：封装复用少传输；缺点：难调试、强绑定、难迁移。

## 50. 索引基本原理是什么？

**通俗理解：** 索引先按某种结构把字段值排好，查询时就不用全表一行行找，而是像查目录一样快速定位。

**专业回答：** 索引通过额外的数据结构维护索引列值与数据记录位置之间的映射。查询时，优化器可以利用索引快速缩小扫描范围，减少磁盘 IO 和比较次数。InnoDB 中常见的 B+ 树索引会按键值有序组织数据，支持等值查询、范围查询和排序优化。

**记忆版：** 索引原理 = 有序结构 + 映射位置 + 减少扫描。

## 51. 索引算法有哪些？

**通俗理解：** 索引不只一种实现方式，常见有 B+ 树和 Hash。不同结构适合不同查询。

**专业回答：** 常见索引算法或结构包括 B+ 树索引、Hash 索引、全文索引、R-Tree 空间索引等。B+ 树适合等值、范围、排序等通用查询；Hash 索引适合等值查询；全文索引用于文本关键词检索；R-Tree 常用于空间数据。

**记忆版：** B+ 树最通用，Hash 查等值，全文查文本，R-Tree 查空间。

## 52. 使用 B 树的好处是什么？

**通俗理解：** B 树不像普通二叉树那样一层只有少量分支，它一个节点可以有很多分支，所以树更矮，查数据时读磁盘次数更少。

**专业回答：** B 树是一种多路平衡查找树，能够保持数据有序，并通过多分支降低树高，减少磁盘 IO 次数。相比普通二叉查找树，B 树更适合外部存储场景，因为数据库和文件系统通常按页读取数据，一个节点可以尽量容纳更多关键字和指针。

**记忆版：** B 树好处：多路、平衡、树矮、少 IO。

## 53. 创建索引的原则是什么？

**通俗理解：** 索引不是越多越好，要给“经常用来找数据、排序、分组、关联”的字段建索引；很少查询、经常大批量修改、区分度很低的字段就要谨慎。

**专业回答：** 创建索引时应优先考虑 `WHERE` 条件列、`JOIN` 关联列、`ORDER BY`/`GROUP BY` 列，以及高区分度字段。联合索引要遵循最左前缀原则，并结合查询条件顺序设计。索引字段应尽量短、稳定，避免在频繁更新字段和低选择性字段上盲目建索引。索引会提升查询定位速度，但会增加存储空间，并降低 `INSERT`、`UPDATE`、`DELETE` 的维护成本。

**记忆版：** 建索引看四点：常查、常连、常排、高区分；别乱建，写入会变慢。

## 54. SQL 的生命周期是什么？

**通俗理解：** 一条 SQL 从客户端发给 MySQL 后，不是马上去磁盘找数据，而是先连接、检查、理解 SQL、选择路线，再真正执行，最后把结果返回。

**专业回答：** SQL 的大致生命周期是：客户端发送 SQL -> 连接器建立连接并校验权限 -> 解析器进行词法和语法分析 -> 预处理阶段检查表、字段、权限等语义信息 -> 优化器生成并选择执行计划 -> 执行器调用存储引擎接口 -> 存储引擎读取或修改数据 -> 返回结果。对于更新语句，还会涉及 undo log、redo log、binlog 等日志配合，以保证事务和崩溃恢复能力。

**记忆版：** SQL 生命周期：连接 -> 解析 -> 优化 -> 执行 -> 返回；更新还要记日志。

## 55. 对于经常变更的数据，为什么有时 CHAR 比 VARCHAR 更好？

**通俗理解：** `CHAR` 像固定长度的格子，每次修改不容易改变位置；`VARCHAR` 像弹性格子，内容变长变短时，可能导致数据页重新整理。

**专业回答：** `CHAR` 是定长字段，更新时长度不变，存储位置更稳定，适合长度固定或变化不大的数据，例如状态码、性别、固定编号等。`VARCHAR` 是变长字段，空间利用率更高，但字段长度频繁变化时，可能带来页内碎片、行迁移或额外维护成本。因此，对于长度固定且频繁更新的短字段，`CHAR` 可能更稳定；对于长度差异明显的字段，`VARCHAR` 更节省空间。

**记忆版：** 长度固定用 `CHAR`，长度变化大用 `VARCHAR`；频繁改且长度固定，`CHAR` 更稳。

## 56. InnoDB 引擎的四大特性是什么？

**通俗理解：** InnoDB 为了让读写更快、更安全，内部做了很多优化：先缓冲写入、避免写坏页、给热点索引加速、提前预读数据。

**专业回答：** 面试中常说的 InnoDB 四大特性通常指：插入缓冲/变更缓冲（Change Buffer）、两次写（Doublewrite Buffer）、自适应哈希索引（Adaptive Hash Index）、预读（Read Ahead）。Change Buffer 用于延迟合并部分二级索引变更，减少随机 IO；Doublewrite 用于防止页写入一半时宕机造成坏页；Adaptive Hash Index 会对热点访问自动建立哈希路径；Read Ahead 会根据访问模式提前读取可能需要的数据页。

**记忆版：** InnoDB 四大特性：变更缓冲、两次写、自适应哈希、预读。

## 57. 什么是游标？

**通俗理解：** 游标像一根指针，可以把查询结果一行一行拿出来处理，而不是一次性整体处理。

**专业回答：** 游标（Cursor）是数据库中用于逐行遍历查询结果集的机制。它适合在存储过程或复杂逻辑中按行处理数据，例如逐条计算、逐条迁移、逐条调用逻辑等。但游标通常性能较差，因为它偏向逐行处理，不能充分发挥 SQL 集合化处理能力。能用一条 SQL 批量完成的场景，应尽量避免使用游标。

**记忆版：** 游标 = 结果集指针；能批量 SQL，就别逐行游标。

## 58. 主键类型有哪些？

**通俗理解：** 主键就是每行数据的身份证。它可以用业务里的天然编号，也可以用系统生成的自增 ID，还可以多个字段一起组成。

**专业回答：** 从设计角度看，主键常见类型包括自然主键、代理主键和联合主键。自然主键来自业务字段，例如身份证号、订单号；代理主键由系统生成，例如自增 `BIGINT`、雪花 ID、UUID；联合主键由多个字段共同保证唯一。InnoDB 中主键也是聚簇索引，建议优先选择短、稳定、递增、无业务含义的代理主键，避免业务变化影响关联关系和索引结构。

**记忆版：** 主键三类：自然主键、代理主键、联合主键；InnoDB 推荐短稳递增。
